## 2. 项目背景

传统电商系统通常由用户商城、后台管理、商品中心、订单中心、库存中心、搜索系统以及权限系统等模块组成。随着大模型和 AI Agent 技术的发展，电商平台可以进一步通过自然语言理解、知识库检索和工具调用，为用户提供智能导购、商品对比、订单咨询等服务，同时帮助后台运营人员完成知识库维护、业务配置和运营分析。

本项目计划构建一个完整的 AI 智能电商平台，业务流程参考主流综合电商平台，但不直接复刻淘宝等现有产品的界面与全部功能。

系统同时包含：

1. 面向消费者的用户商城端；
2. 面向平台工作人员的后台管理端；
3. 基于 Java 和 Spring Cloud Alibaba 的微服务后端；
4. 基于 Python、FastAPI、RAG 和 AI Agent 的独立 AI 服务；
5. 支撑系统运行的数据库、缓存、消息队列、搜索引擎和对象存储等基础设施。

本项目重点不在于堆积页面数量，而在于完整实现商品发布、商城购买、库存锁定、订单支付、后台发货、用户收货等电商核心业务闭环，并体现 Java 微服务、DDD 领域建模、分布式系统和 AI 业务融合能力。

## 3. 项目目标

### 3.1 业务目标

构建一个可以完整运行和演示的电商平台，实现以下核心业务：

- 后台创建并发布商品；
- 商城展示、搜索和筛选商品；
- 用户选择 SKU 并加入购物车；
- 用户提交订单并完成模拟支付；
- 系统锁定、扣减和释放库存；
- 后台处理发货和退款；
- 用户查看订单并确认收货；
- 后台配置角色、菜单、权限和系统功能；
- AI 根据真实商品和订单数据提供智能服务。

通过项目重点实践以下技术能力：

## 4. 项目定位

本项目定位为：

> 一个以电商交易业务为核心，以 Java 微服务和 DDD 为后端架构基础，同时融合 AI 智能导购、商品对比、知识库客服和订单助手能力的综合电商平台。

项目具有以下特点。

### 4.1 完整业务平台

项目不是单独的商城页面，也不是单独的后台系统，而是由商城、后台、业务后端和 AI 服务共同组成的完整系统。

### 4.2 多前端应用

用户商城端和后台管理端采用两个独立的 Vue3 应用：

- 商城端面向消费者；
- 后台端面向管理员和运营人员；
- 两个应用独立开发、打包和部署；
- 两个应用共同访问同一套后端业务服务。

本项目不采用微前端架构。

### 4.3 Java 微服务后端

后端按照身份权限、会员、商品、购物车、订单、库存、搜索和系统配置等业务边界进行拆分。

各微服务：

- 独立启动；
- 独立注册到 Nacos；
- 通过 Gateway 统一访问；
- 通过 OpenFeign 或 RocketMQ 通信；
- 原则上独立管理自己的数据。

### 4.4 DDD 领域驱动设计

核心业务服务内部采用 DDD 分层：

- `interfaces`：接口层；
- `application`：应用层；
- `domain`：领域层；
- `infrastructure`：基础设施层。

重点通过聚合根封装订单状态流转、库存锁定、商品上下架、角色授权和功能配置等业务规则。

### 4.5 AI 与真实业务融合

AI 不仅提供普通聊天功能，而是通过调用 Java 后端提供的商品、订单和知识库接口完成真实业务查询。

AI 推荐的商品必须来自真实商品数据，AI 查询的订单必须属于当前登录用户。

## 7. 核心业务范围

### 7.1 商品业务

商品业务包括：

- SPU 管理；
- SKU 管理；
- 分类管理；
- 品牌管理；
- 商品属性；
- 商品图片；
- 商品价格；
- 商品上下架；
- 商品状态校验；
- 商品详情缓存；
- 搜索索引同步。

商品发布基本流程：

```text
后台创建 SPU
→ 配置 SKU
→ 上传商品图片
→ 设置价格
→ 初始化库存
→ 商品上架
→ 同步搜索索引
→ 商城展示商品
```

### 7.2 购物车业务

购物车业务包括：

- 添加 SKU；
- 修改商品数量；
- 删除商品；
- 选中或取消选中；
- 商品状态校验；
- 实时价格校验；
- 库存校验；
- 失效商品处理；
- 登录前后购物车合并。

购物车主要使用 Redis 存储。

### 7.3 订单业务

订单业务包括：

- 订单预览；
- 创建订单；
- 订单明细快照；
- 模拟支付；
- 取消订单；
- 超时关闭；
- 后台发货；
- 确认收货；
- 退款申请；
- 退款审核；
- 订单状态记录。

订单状态暂定为：

```text
待付款
待发货
已发货
已完成
已取消
退款中
已退款
```

订单需要保存：

- 商品名称快照；
- SKU 规格快照；
- 成交价格快照；
- 商品图片快照；
- 收货地址快照。

### 7.4 库存业务

库存业务包括：

- 库存初始化；
- 库存增加；
- 可用库存查询；
- 库存锁定；
- 锁定库存释放；
- 支付成功后确认扣减；
- 库存流水；
- 低库存预警。

核心流程：

```text
提交订单
→ 锁定库存
→ 创建待付款订单
→ 支付成功
→ 确认扣减库存
```

订单关闭时：

```text
订单取消或超时
→ 释放锁定库存
```

库存必须保证：

- 可用库存不能小于零；
- 锁定库存不能小于零；
- 不允许超卖；
- 同一个业务请求不能重复锁定或重复扣减。

### 7.5 权限业务

后台采用 RBAC 权限模型：

```text
管理员
→ 角色
→ 菜单
→ 权限
```

权限类型包括：

- 目录权限；
- 页面权限；
- 按钮权限；
- 接口权限。

动态菜单流程：

```text
管理员登录
→ 查询角色
→ 查询角色菜单
→ 查询权限编码
→ 返回菜单树和权限集合
→ Vue 动态注册路由
→ 渲染侧边栏和操作按钮
```

后端使用 Spring Security 对接口权限进行最终校验。

### 7.6 功能配置业务

后台可以动态配置：

- AI 智能导购开关；
- AI 商品对比开关；
- 商品评价开关；
- 用户注册开关；
- 订单退款开关；
- 收藏功能开关；
- 模拟支付开关；
- 商品审核开关。

同时支持业务参数配置：

- 订单超时时间；
- 自动确认收货天数；
- 购物车最大商品数量；
- 单个 SKU 最大购买数量；
- AI 最大对话轮数；
- 文件上传大小限制。

功能配置修改后需要：

```text
更新数据库
→ 清理 Redis 缓存
→ 商城重新获取配置
→ 前端入口动态变化
→ 后端接口同步校验
```

## 8. AI 功能范围

### 8.1 AI 智能导购

用户通过自然语言描述：

- 预算；
- 商品品类；
- 使用场景；
- 品牌偏好；
- 功能需求。

AI 对需求进行结构化解析，并调用商品搜索接口，返回真实商品及推荐理由。

示例：

```text
预算 3000 元以内，想买一台适合学习编程的轻薄笔记本。
```

AI 需要完成：

```text
识别意图
→ 提取预算和需求
→ 调用商品搜索工具
→ 获取真实商品
→ 排序和筛选
→ 生成推荐理由
→ 返回结构化商品卡片
```

### 8.2 AI 商品对比

用户选择两个或多个商品，AI 根据真实商品参数进行对比。

对比维度包括：

- 价格；
- 规格参数；
- 主要优点；
- 主要缺点；
- 适用场景；
- 推荐人群；
- 性价比。

### 8.3 RAG 智能客服

知识库内容包括：

- 发货规则；
- 退款规则；
- 退换货政策；
- 支付说明；
- 平台规则；
- 商品使用说明。

AI 回答应尽量返回知识来源，减少模型幻觉。

### 8.4 AI 订单助手

AI Agent 可以调用：

- 订单列表查询；
- 订单详情查询；
- 发货状态查询；
- 退款进度查询；
- 取消订单；
- 申请退款。

涉及取消订单和申请退款等写操作时，需要用户二次确认。

### 8.5 AI 功能约束

AI 服务必须遵守以下原则：

- 不直接访问各业务服务数据库；
- 通过 Java 内部接口获取商品和订单数据；
- 不凭空生成平台不存在的商品；
- 不查询不属于当前用户的订单；
- 写操作必须经过 Java 服务权限与业务校验；
- AI 服务不可用时不能影响基础购物流程。

## 11. DDD 架构原则

核心微服务内部采用以下分层：

```text
interfaces
application
domain
infrastructure
```

### 11.1 Interfaces 接口层

负责：

- REST API；
- OpenFeign 接口；
- MQ 消息监听；
- 定时任务入口；
- 请求参数转换。

### 11.2 Application 应用层

负责：

- 编排业务用例；
- 处理 Command 和 Query；
- 控制事务；
- 调用领域对象；
- 调用其他上下文；
- 发布领域事件或集成事件；
- 返回 DTO。

### 11.3 Domain 领域层

负责：

## 12. 服务通信与数据一致性

### 12.1 同步通信

适合需要立即返回结果的场景：

- 查询商品快照；
- 查询用户地址；
- 锁定库存；
- 查询功能配置；
- AI 查询商品和订单数据。

同步通信主要采用 OpenFeign 或内部 HTTP API。

### 12.2 异步通信

适合业务解耦和最终一致性的场景：

- 订单创建；
- 订单支付成功；
- 订单取消；
- 商品上架；
- 商品下架；
- 搜索索引更新；
- 功能配置修改；
- 操作日志记录。

异步通信主要使用 RocketMQ。

### 12.3 数据一致性方案

项目采用：

```text
本地事务
+ 消息队列
+ 接口幂等
+ 消息重试
+ 状态补偿
```

第一阶段不引入复杂的分布式事务框架。

订单、库存等核心操作必须具备：

- 唯一业务编号；
- 幂等校验；
- 状态合法性校验；
- 异常补偿能力。

## 16. 核心验收链路

第一版完成后，至少需要完整演示以下业务链路。

### 16.1 商品发布链路

```text
后台创建商品
→ 配置 SKU
→ 初始化库存
→ 商品上架
→ 商城显示商品
```

### 16.2 用户购物链路

```text
用户登录
→ 浏览商品
→ 选择 SKU
→ 加入购物车
→ 提交订单
→ 锁定库存
→ 模拟支付
→ 确认扣减库存
```

### 16.3 订单履约链路

```text
后台查看待发货订单
→ 管理员发货
→ 商城显示已发货
→ 用户确认收货
→ 订单完成
```

### 16.4 超时订单链路

```text
创建待付款订单
→ 发送延迟消息
→ 到期检查订单状态
→ 未支付则关闭订单
→ 释放锁定库存
```

### 16.5 权限管理链路

```text
超级管理员创建角色
→ 分配菜单和按钮权限
→ 管理员重新登录
→ 动态加载菜单
→ 显示授权按钮
→ 未授权接口访问被拒绝
```

### 16.6 功能配置链路

```text
后台关闭 AI 导购
→ 更新功能配置
→ 清除配置缓存
→ 商城隐藏 AI 入口
→ 后端 AI 接口禁止调用
```

### 16.7 AI 导购链路

```text
用户描述购买需求
→ AI 解析需求
→ 调用商品搜索接口
→ 返回真实商品
→ 生成推荐理由
→ 商城展示商品卡片
```

## 18. 项目开发原则

项目开发遵循以下原则：

1. 先确定业务边界，再设计数据库；
2. 先完成核心交易链路，再增加 AI；
3. 先保证业务正确，再进行性能优化；
4. 核心业务使用 DDD，技术型模块避免过度设计；
5. 商城端和后台端独立开发，不采用微前端；
6. 服务之间通过接口和事件通信，不直接访问其他服务的数据表；
7. 领域对象不直接作为数据库对象或接口返回对象；
8. 前端权限只负责展示，后端权限负责最终安全校验；
9. AI 不直接操作数据库，所有业务操作必须经过 Java 服务；
10. 每个开发阶段必须具有可验证的验收结果。
