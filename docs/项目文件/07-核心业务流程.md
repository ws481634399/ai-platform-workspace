## 3. 流程设计原则

### 3.1 核心交易优先保证正确性

订单、支付和库存流程优先保证：

- 状态正确；
- 金额正确；
- 库存正确；
- 幂等；
- 可补偿；
- 可追踪。

不得为了简化页面体验而绕过后端业务规则。

### 3.2 前端不作为业务安全边界

前端可以：

- 隐藏按钮；
- 禁用操作；
- 提示用户；
- 防止重复点击。

但后端仍必须进行：

- 身份校验；
- 权限校验；
- 状态校验；
- 数据归属校验；
- 幂等校验；
- 参数校验。

### 3.3 同步与异步合理划分

同步调用用于：

- 用户正在等待结果；
- 必须立即判断成功或失败；
- 需要返回明确业务结果。

异步事件用于：

- 搜索索引同步；
- 操作日志；
- 订单超时；
- 支付后库存确认扣减；
- 订单取消后库存释放；
- AI 文档解析；
- 统计和通知。

### 3.4 所有跨服务写操作必须幂等

重点包括：

- 创建订单；
- 锁定库存；
- 释放库存；
- 确认扣减库存；
- 支付；
- 取消订单；
- 发货；
- 退款审核；
- 搜索索引更新；
- 配置变更事件消费。

### 3.5 失败必须有明确处理方式

每个关键步骤必须明确：

- 直接失败；
- 重试；
- 回滚；
- 补偿；
- 降级；
- 记录告警；
- 人工处理。

# 5. 会员注册流程

## 5.1 流程目标

游客创建商城会员账号，并获得可登录身份。

## 5.2 参与方

- 游客；
- `mall-web`；
- `mall-gateway`；
- `mall-identity`；
- `mall-member`；
- `mall-system`。

## 5.3 正常流程

```mermaid
sequenceDiagram
    actor Guest as 游客
    participant Web as mall-web
    participant Gateway as mall-gateway
    participant System as mall-system
    participant Identity as mall-identity
    participant Member as mall-member

    Guest->>Web: 填写注册信息
    Web->>Gateway: POST /api/auth/member/register
    Gateway->>System: 查询注册功能开关
    System-->>Gateway: 已启用
    Gateway->>Identity: 创建会员账号
    Identity->>Identity: 校验账号唯一性与密码规则
    Identity->>Member: 创建会员资料
    Member-->>Identity: MemberId
    Identity->>Identity: 保存登录凭据
    Identity-->>Gateway: 注册成功
    Gateway-->>Web: 返回注册结果
    Web-->>Guest: 跳转登录或自动登录
```

## 5.4 业务步骤

1. 游客进入注册页；
2. 前端读取 `member.register.enabled`；
3. 用户填写账号和密码；
4. 后端再次检查注册功能是否启用；
5. 校验账号格式；
6. 校验账号唯一性；
7. 校验密码强度；
8. 密码加密；
9. 创建会员业务资料；
10. 创建会员认证账号；
11. 返回注册结果；
12. 记录注册日志。

## 5.5 本地事务边界

如果会员账号和会员资料在不同服务：

```text
mall-identity 本地事务
mall-member 本地事务
```

不能使用跨库事务。

第一版建议流程：

```text
先创建 Member
→ 再创建认证账号
```

若认证账号创建失败：

```text
记录补偿任务
→ 禁用或删除未完成会员资料
```

也可以使用注册 Saga，但第一版不强制。

## 5.6 异常路径

| 异常 | 处理 |
|---|---|
| 注册功能关闭 | 返回“当前暂不开放注册” |
| 账号已存在 | 拒绝注册 |
| 密码不符合规则 | 返回明确提示 |
| 会员服务不可用 | 注册失败 |
| 账号创建成功但会员资料失败 | 回滚账号本地事务 |
| 会员资料成功但账号创建失败 | 记录补偿并清理孤立资料 |

## 5.7 验收标准

- 正常信息可注册；
- 重复账号不能注册；
- 密码不合规不能注册；
- 功能关闭后前后端均不可注册；
- 密码不以明文保存；
- 注册失败不会留下可登录但无会员资料的账号。

# 6. 会员登录流程

## 6.1 流程目标

会员通过账号和密码登录商城，并获得访问令牌。

## 6.2 正常流程

```mermaid
sequenceDiagram
    actor MemberUser as 会员
    participant Web as mall-web
    participant Gateway as mall-gateway
    participant Identity as mall-identity
    participant Cart as mall-cart

    MemberUser->>Web: 输入账号和密码
    Web->>Gateway: POST /api/auth/member/login
    Gateway->>Identity: 登录请求
    Identity->>Identity: 校验账号、密码和状态
    Identity->>Identity: 生成 Access Token / Refresh Token
    Identity-->>Gateway: 返回令牌和 MemberId
    Gateway-->>Web: 登录成功
    Web->>Cart: 合并游客购物车
    Cart-->>Web: 合并结果
    Web-->>MemberUser: 进入商城
```

## 6.3 业务规则

- 禁用会员不能登录；
- 密码错误不暴露账号是否存在；
- Token 必须包含身份类型；
- 商城 Token 不允许访问后台接口；
- 游客购物车合并失败不影响登录成功；
- 登录成功后恢复用户信息和购物车。

## 6.4 异常路径

| 异常 | 处理 |
|---|---|
| 账号或密码错误 | 返回统一错误提示 |
| 账号已禁用 | 拒绝登录 |
| 账号已锁定 | 提示稍后重试或联系管理员 |
| Token 生成失败 | 登录失败 |
| 购物车合并失败 | 登录成功，提示购物车同步失败 |

## 6.5 验收标准

- 正确账号可登录；
- 错误密码不能登录；
- 禁用用户不能登录；
- 商城 Token 不能访问后台接口；
- 登录后可访问个人订单；
- 游客购物车可正确合并。

# 7. 后台管理员登录与动态菜单流程

## 7.1 流程目标

管理员登录后台后，根据角色动态加载菜单、页面和按钮权限。

## 7.2 参与方

- 后台管理员；
- `mall-admin`；
- `mall-gateway`；
- `mall-identity`；
- Redis。

## 7.3 正常流程

```mermaid
sequenceDiagram
    actor Admin as 管理员
    participant Web as mall-admin
    participant Gateway as mall-gateway
    participant Identity as mall-identity
    participant Redis as Redis

    Admin->>Web: 输入账号和密码
    Web->>Gateway: POST /api/auth/admin/login
    Gateway->>Identity: 管理员登录
    Identity->>Identity: 校验账号、密码和状态
    Identity->>Identity: 查询角色
    Identity->>Identity: 查询角色菜单与权限
    Identity->>Redis: 缓存权限信息
    Identity-->>Gateway: Token + 管理员信息
    Gateway-->>Web: 登录成功
    Web->>Gateway: GET /api/admin/current-user/menus
    Gateway->>Identity: 查询菜单树和权限集合
    Identity-->>Web: 菜单树 + PermissionCodes
    Web->>Web: 动态注册路由
    Web->>Web: 渲染侧边栏和按钮
```

## 7.4 业务步骤

1. 管理员提交登录；
2. 校验管理员账号；
3. 校验密码；
4. 校验管理员状态；
5. 查询有效角色；
6. 查询角色菜单；
7. 过滤禁用菜单；
8. 构建菜单树；
9. 汇总权限编码；
10. 生成后台 Token；
11. 前端获取菜单树；
12. 前端调用 `router.addRoute()`；
13. 前端根据权限编码控制按钮；
14. 后端接口继续使用 Spring Security 校验。

## 7.5 菜单类型

```text
DIRECTORY
PAGE
BUTTON
```

## 7.6 刷新页面流程

```text
页面刷新
→ 读取本地 Token
→ 请求当前用户菜单
→ 重新注册动态路由
→ 恢复页面
```

## 7.7 权限变更生效

第一版建议：

```text
管理员重新登录后生效
```

P1 可增强：

```text
角色权限版本变更
→ 清理 Redis 权限缓存
→ 当前用户下次请求重新加载
```

## 7.8 异常路径

| 异常 | 处理 |
|---|---|
| 管理员禁用 | 拒绝登录 |
| 角色禁用 | 不加载该角色权限 |
| 无任何角色 | 可登录但只能看到无权限页，或直接拒绝后台登录 |
| 菜单组件路径不存在 | 前端跳过并记录错误 |
| 权限缓存不可用 | 回源数据库 |
| 直接访问无权限页面 | 路由守卫拒绝 |
| 直接调用无权限接口 | 后端返回 403 |

## 7.9 验收标准

- 不同角色看到不同菜单；
- 无权限按钮不显示；
- 手动输入无权限路由不能访问；
- 直接调用无权限 API 返回 403；
- 刷新页面后动态路由可恢复；
- 退出登录后动态路由被清理。

# 8. 角色授权流程

## 8.1 流程目标

超级管理员为角色分配目录、页面和按钮权限。

## 8.2 正常流程

```text
超级管理员进入角色管理
→ 选择角色
→ 加载菜单权限树
→ 勾选目录、页面和按钮
→ 提交授权
→ 后端校验角色状态
→ 后端校验菜单有效性
→ 替换角色菜单关系
→ 清理权限缓存
→ 记录操作日志
```

## 8.3 业务规则

- 只有具备 `system:role:update` 权限的管理员可授权；
- 内置超级管理员角色不能被清空；
- 禁用菜单不能授予；
- 权限编码必须唯一；
- 授权提交采用覆盖式更新；
- 角色菜单关系在本地事务内更新；
- 变更后清理相关管理员权限缓存。

## 8.4 幂等要求

相同菜单集合重复提交：

```text
结果不变
```

## 8.5 验收标准

- 可以创建商品管理员角色；
- 只授予商品菜单；
- 登录后只显示商品相关内容；
- 无订单发货权限时无法调用发货接口。

# 9. 商品创建流程

## 9.1 流程目标

商品管理员创建商品 SPU，并配置基础信息。

## 9.2 正常流程

```mermaid
sequenceDiagram
    actor Admin as 商品管理员
    participant Web as mall-admin
    participant Gateway as mall-gateway
    participant Product as mall-product
    participant MinIO as MinIO

    Admin->>Web: 填写商品基础信息
    Web->>MinIO: 上传商品图片
    MinIO-->>Web: 返回对象地址
    Web->>Gateway: POST /api/admin/products
    Gateway->>Product: 创建商品
    Product->>Product: 校验分类、品牌、名称和图片
    Product->>Product: 创建 Product 聚合
    Product->>Product: 保存草稿商品
    Product-->>Web: 返回 ProductId
```

## 9.3 业务步骤

1. 管理员进入商品创建页；
2. 选择分类；
3. 选择品牌；
4. 填写商品名称和描述；
5. 上传主图和详情图；
6. 前端提交创建请求；
7. 后端校验权限；
8. 校验分类有效；
9. 校验品牌有效；
10. 校验商品编码唯一；
11. 创建 Product 聚合；
12. 状态设置为 `DRAFT`；
13. 保存商品；
14. 记录操作日志。

## 9.4 业务规则

- 商品名称不能为空；
- 商品编码唯一；
- 主图只能有一张；
- 商品初始状态为草稿；
- 草稿不能在商城显示；
- 商品创建不自动初始化库存；
- 商品创建不自动上架。

## 9.5 异常路径

| 异常 | 处理 |
|---|---|
| 分类不存在 | 创建失败 |
| 品牌不存在 | 创建失败 |
| 商品编码重复 | 创建失败 |
| 图片上传失败 | 不提交商品或允许保存无图草稿 |
| 商品保存失败 | 返回失败，已上传孤立文件后续清理 |

# 10. SKU 配置流程

## 10.1 流程目标

为商品创建可销售规格，并设置价格。

## 10.2 正常流程

```text
管理员打开商品编辑页
→ 添加规格维度
→ 生成 SKU 组合
→ 设置 SKU 编码
→ 设置销售价格
→ 设置 SKU 图片
→ 提交 SKU 配置
→ Product 聚合校验
→ SKU 已添加
```

## 10.3 业务规则

- SKU 编码唯一；
- 同一商品中规格组合唯一；
- 价格不能小于零；
- SKU 默认状态可设置为启用；
- SKU 没有初始化库存时仍不可完成交易；
- 商品上架后修改 SKU 需要触发搜索索引更新。

## 10.4 验收标准

- 可创建多个 SKU；
- 重复规格组合被拒绝；
- 负价格被拒绝；
- SKU 修改不影响历史订单；
- 禁用 SKU 不能购买。

# 11. 库存初始化流程

## 11.1 流程目标

为 SKU 创建初始库存记录。

## 11.2 参与方

- 商品管理员；
- `mall-admin`；
- `mall-inventory`；
- `mall-product`。

## 11.3 正常流程

```mermaid
sequenceDiagram
    actor Admin as 商品管理员
    participant Web as mall-admin
    participant Product as mall-product
    participant Inventory as mall-inventory

    Admin->>Web: 输入 SKU 初始库存
    Web->>Product: 校验 SKU 存在
    Product-->>Web: SKU 有效
    Web->>Inventory: 初始化库存
    Inventory->>Inventory: 检查是否已初始化
    Inventory->>Inventory: 创建 Inventory 聚合
    Inventory->>Inventory: 创建库存流水
    Inventory-->>Web: 初始化成功
```

## 11.4 业务规则

- SKU 必须存在；
- 同一 SKU 只能初始化一次；
- 初始库存不能小于零；
- 初始可用库存等于总库存；
- 锁定库存为零；
- 已售数量为零；
- 生成库存流水；
- 初始化操作需要库存权限。

## 11.5 幂等要求

以 `skuId` 唯一约束保证：

```text
重复初始化不重复创建库存
```

## 11.6 验收标准

- 新 SKU 可以初始化；
- 重复初始化被拒绝或返回原结果；
- 负数库存被拒绝；
- 初始化后后台可查询；
- 初始化后商品满足库存上架条件。

# 12. 商品上架流程

## 12.1 流程目标

将满足条件的草稿或已下架商品设置为可售状态。

## 12.2 正常流程

```mermaid
sequenceDiagram
    actor Admin as 商品管理员
    participant Web as mall-admin
    participant Product as mall-product
    participant Inventory as mall-inventory
    participant MQ as RocketMQ
    participant Search as mall-search

    Admin->>Web: 点击上架
    Web->>Product: POST /api/admin/products/{id}/publish
    Product->>Product: 加载 Product 聚合
    Product->>Inventory: 查询 SKU 库存初始化状态
    Inventory-->>Product: 返回初始化结果
    Product->>Product: 校验上架条件
    Product->>Product: product.publish()
    Product->>Product: 保存商品
    Product->>MQ: 发布 ProductPublishedIntegrationEvent
    Product-->>Web: 上架成功
    MQ->>Search: 消费商品上架事件
    Search->>Product: 获取搜索投影数据
    Product-->>Search: 商品索引数据
    Search->>Search: 更新 Elasticsearch
```

## 12.3 上架条件

- 商品基础信息完整；
- 分类有效；
- 品牌有效；
- 主图存在；
- 至少一个 SKU；
- 至少一个启用 SKU；
- SKU 价格合法；
- SKU 规格组合合法；
- 至少一个可售 SKU 已初始化库存；
- 商品未被禁用。

## 12.4 事务边界

商品上架本地事务：

```text
修改 Product 状态
+
保存领域事件或 Outbox
```

搜索索引更新不参与商品本地事务。

## 12.5 异常路径

| 异常 | 处理 |
|---|---|
| 商品资料不完整 | 返回缺失项 |
| 无有效 SKU | 拒绝上架 |
| 库存未初始化 | 拒绝上架 |
| 商品已禁用 | 拒绝上架 |
| 商品保存失败 | 上架失败 |
| MQ 发送失败 | 本地消息重试 |
| 搜索索引失败 | 搜索服务重试或补偿 |

## 12.6 验收标准

- 满足条件商品可上架；
- 不满足条件不能上架；
- 上架后商城商品列表可见；
- 搜索索引延迟后可搜索；
- 搜索失败不回滚商品上架；
- 无权限管理员不能上架。

# 19. 创建订单与库存锁定流程

## 19.1 流程目标

会员提交订单，系统锁定库存并创建待付款订单。

## 19.2 正常流程

```mermaid
sequenceDiagram
    actor Member as 会员
    participant Web as mall-web
    participant Order as mall-order
    participant Product as mall-product
    participant MemberSvc as mall-member
    participant Inventory as mall-inventory
    participant Cart as mall-cart
    participant MQ as RocketMQ

    Member->>Web: 点击提交订单
    Web->>Order: POST /api/mall/orders
    Order->>Order: 校验幂等令牌
    Order->>Product: 获取最新商品快照和价格
    Product-->>Order: 返回有效商品数据
    Order->>MemberSvc: 校验收货地址
    MemberSvc-->>Order: 地址有效
    Order->>Order: 生成 OrderNo 和金额
    Order->>Inventory: 锁定库存
    Inventory->>Inventory: 本地事务锁定多个 SKU
    Inventory-->>Order: ReservationNo
    Order->>Order: 创建 Order 聚合
    Order->>Order: 保存订单和明细
    Order->>MQ: 发布 OrderCreatedIntegrationEvent
    Order->>Cart: 清理已结算购物车项
    Order-->>Web: 返回待付款订单
```

## 19.3 核心步骤

1. 获取当前会员；
2. 校验幂等令牌；
3. 校验提交商品非空；
4. 查询商品和 SKU；
5. 校验商品可售状态；
6. 获取最新价格；
7. 校验收货地址；
8. 生成订单号；
9. 计算订单金额；
10. 调用库存服务锁定库存；
11. 创建订单和订单明细；
12. 保存商品快照和地址快照；
13. 初始状态设为待付款；
14. 保存支付截止时间；
15. 发布订单已创建事件；
16. 清理购物车；
17. 返回订单结果。

## 19.4 事务边界

### 库存服务

```text
批量锁定库存
+
创建库存锁定记录
+
创建库存流水
```

在库存服务本地事务内完成。

### 订单服务

```text
创建订单
+
创建订单明细
+
创建初始状态记录
+
保存 Outbox 事件
```

在订单服务本地事务内完成。

## 19.5 幂等策略

### 订单幂等

```text
idempotencyToken 唯一
```

### 库存锁定幂等

```text
businessNo + skuId 唯一
```

### 数据库约束

- 订单号唯一；
- 幂等令牌唯一；
- 库存业务锁定唯一；
- 锁定记录编号唯一。

## 19.6 异常路径一：库存不足

```text
请求锁定库存
→ 某 SKU 可用库存不足
→ 库存服务整体返回失败
→ 不创建订单
→ 返回库存不足商品
```

## 19.7 异常路径二：库存锁定成功，订单创建失败

```mermaid
flowchart TD
    A[库存锁定成功] --> B[订单保存失败]
    B --> C[同步调用库存释放]
    C --> D{释放是否成功}
    D -- 是 --> E[返回下单失败]
    D -- 否 --> F[记录库存补偿任务]
    F --> G[定时重试释放]
```

## 19.8 异常路径三：购物车清理失败

```text
订单已创建
→ 清理购物车失败
→ 订单不回滚
→ 记录补偿
→ 用户可手动删除或后续自动清理
```

## 19.9 异常路径四：重复提交

```text
相同 idempotencyToken 再次提交
→ 返回已创建订单
或
→ 返回重复提交提示
```

推荐返回原订单结果，用户体验更好。

## 19.10 验收标准

- 正常下单生成待付款订单；
- 库存不足时不创建订单；
- 重复提交不创建重复订单；
- 订单金额由后端计算；
- 商品和地址快照完整；
- 订单保存失败后库存最终释放；
- 购物车清理失败不影响订单有效性。

# 20. 模拟支付流程

## 20.1 流程目标

用户对待付款订单执行模拟支付，订单变为待发货，并触发库存确认扣减。

## 20.2 正常流程

```mermaid
sequenceDiagram
    actor Member as 会员
    participant Web as mall-web
    participant Order as mall-order
    participant MQ as RocketMQ
    participant Inventory as mall-inventory

    Member->>Web: 点击模拟支付
    Web->>Order: POST /api/mall/orders/{id}/pay
    Order->>Order: 校验订单归属和状态
    Order->>Order: 创建支付记录
    Order->>Order: order.pay()
    Order->>Order: 保存订单与支付记录
    Order->>MQ: 发布 PaymentSucceededIntegrationEvent
    Order-->>Web: 支付成功，订单待发货
    MQ->>Inventory: 消费支付成功事件
    Inventory->>Inventory: 确认扣减锁定库存
    Inventory->>Inventory: 保存库存流水
```

## 20.3 业务规则

- 只有待付款订单可支付；
- 会员只能支付自己的订单；
- 超时订单不能支付；
- 已取消订单不能支付；
- 支付操作必须幂等；
- 支付成功后订单状态为待发货；
- 库存确认扣减基于原锁定记录；
- 重复支付事件不重复扣减库存。

## 20.4 事务边界

订单服务本地事务：

```text
支付记录
+
订单状态
+
支付成功 Outbox
```

库存确认扣减异步完成。

## 20.5 异常路径

### 订单已支付

```text
重复支付
→ 返回原支付成功结果
→ 不重复发布业务结果
```

### 订单已超时

```text
支付请求
→ 发现支付截止时间已过
→ 拒绝支付
→ 可触发订单超时取消
```

### 库存确认扣减失败

```text
PaymentSucceeded 事件
→ 库存消费失败
→ MQ 重试
→ 超过次数进入补偿任务
→ 告警
```

## 20.6 验收标准

- 待付款订单可支付；
- 支付后状态变为待发货；
- 重复支付不重复处理；
- 已取消订单不能支付；
- 库存锁定最终转为已售；
- 库存消费失败可重试。

# 22. 订单超时取消流程

## 22.1 流程目标

待付款订单超过支付截止时间后自动取消。

## 22.2 正常流程

```mermaid
sequenceDiagram
    participant Order as mall-order
    participant MQ as RocketMQ
    participant Inventory as mall-inventory

    Order->>MQ: 创建订单后发送延迟消息
    MQ->>Order: 到期投递订单超时检查
    Order->>Order: 查询订单状态和截止时间
    alt 仍为待付款且已超时
        Order->>Order: cancelForTimeout()
        Order->>Order: 保存订单
        Order->>MQ: 发布 OrderCancelledIntegrationEvent
        MQ->>Inventory: 释放锁定库存
    else 已支付或已取消
        Order->>Order: 忽略消息
    end
```

## 22.3 业务规则

- 超时时间来自系统参数；
- 创建订单时保存实际支付截止时间；
- 参数后续变化不影响已有订单；
- 延迟消息到达时重新检查状态；
- 重复消息幂等；
- 已支付订单不能取消；
- 库存释放最终一致。

## 22.4 补偿机制

除延迟消息外，增加定时任务：

```text
扫描超时待付款订单
→ 补偿取消
```

避免延迟消息丢失。

## 22.5 验收标准

- 超时未支付订单自动取消；
- 已支付订单不被误取消；
- 重复延迟消息不重复处理；
- 库存最终释放；
- 定时补偿可处理漏单。

# 36. 服务降级总览

| 服务 | 不可用影响 | 降级策略 |
|---|---|---|
| mall-identity | 无法登录或鉴权 | 拒绝受保护请求 |

| mall-search | 无法搜索 | 降级分类浏览或 MySQL 简单搜索 |
| mall-system | 无法读取配置 | 使用最后缓存或安全默认值 |
| ai-service | AI 不可用 | 返回传统搜索和客服入口 |
| RocketMQ | 异步事件受阻 | 本地消息重试与补偿 |
| Elasticsearch | 搜索不可用 | 分类浏览或 MySQL 降级 |
| MinIO | 文件上传不可用 | 暂停上传，不影响已存在文件 |
| Redis | 缓存和购物车受影响 | 部分回源数据库，购物车明确失败 |

# 41. 当前流程决策

## 41.1 已确定

- 商品创建后默认为草稿；
- SKU 属于 Product 聚合内部实体；
- 库存按 SKU 独立管理；
- 订单预览不锁定库存；
- 提交订单时同步锁定库存；
- 订单创建失败同步释放库存；
- 支付后异步确认扣减库存；
- 取消后异步释放库存；
- 订单创建时保存商品和地址快照；
- 订单超时使用 RocketMQ 延迟消息和定时补偿；
- 退款第一版采用整单模拟退款；
- 动态菜单由后端返回；
- AI 不直接访问业务数据库；
- AI 写操作必须二次确认。

## 41.2 待确认

- 购物车清理采用同步还是异步；
- 是否采用 Outbox；
- 是否使用 RocketMQ 事务消息；
- 退款完成后是否回补库存；
- 商品上架是否强制所有启用 SKU 初始化库存；
- 后台角色权限是否实时失效；
- 文件孤立对象清理周期；
- 内部服务认证方式；
- AI 会话保存期限；
- Elasticsearch 降级是否在第一版实现。
