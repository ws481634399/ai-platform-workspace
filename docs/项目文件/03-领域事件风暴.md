## 2. 文档目的

本文档使用事件风暴方法，从业务事实出发梳理 AI 智能电商微服务平台的核心业务流程，并识别：

- 参与者；
- 命令；
- 领域事件；
- 聚合；
- 业务规则；
- 自动化策略；
- 查询模型；
- 外部系统；
- 跨上下文协作；
- 业务异常；
- 设计热点；
- 潜在限界上下文。

本文档重点解决以下问题：

1. 系统中发生了哪些关键业务事实；
2. 谁触发这些业务事实；
3. 触发前需要执行什么命令；
4. 哪个聚合负责处理命令；
5. 事件发生后需要触发哪些后续动作；
6. 哪些流程需要同步完成；
7. 哪些流程适合通过消息异步完成；
8. 哪些环节存在一致性、幂等、并发和权限风险；
9. 不同业务模型应如何划分边界。

本文档是后续《子域与限界上下文》《上下文映射图》《聚合与领域模型设计》的直接输入。

## 3. 事件风暴建模约定

### 3.1 建模元素

本文档使用以下元素。

| 元素 | 含义 | 示例 |
|---|---|---|
| 参与者 Actor | 发起业务行为的人或系统 | 会员、商品管理员、订单管理员 |
| 命令 Command | 希望系统执行并改变状态的意图 | 创建商品、提交订单、锁定库存 |
| 领域事件 Domain Event | 在当前业务上下文内已经发生的事实 | 商品已上架、订单已创建 |
| 集成事件 Integration Event | 需要通知其他微服务的业务事实 | 商品已上架、订单已取消 |
| 聚合 Aggregate | 执行业务规则并维护一致性的领域对象 | 商品、订单、库存、角色 |
| 策略 Policy | 某个事件发生后自动执行的规则 | 订单已创建后发送延迟关闭消息 |
| 查询模型 Read Model | 供用户或系统读取的信息视图 | 商品详情、订单详情、后台订单列表 |
| 外部系统 External System | 不属于当前领域模型的系统 | MinIO、RocketMQ、Elasticsearch、大模型服务 |
| 热点 Hotspot | 尚未确定或存在风险的业务问题 | 订单创建失败后库存如何补偿 |

### 3.2 事件命名规则

事件表示已经发生的事实，统一采用过去式：

```text
商品已创建
商品已上架
库存已锁定
订单已创建
支付已成功
订单已发货
订单已完成
```

禁止使用尚未完成的动作作为事件：

```text
创建订单
支付订单
进行发货
```

以上属于命令，不属于事件。

### 3.3 时间方向

事件风暴按照从左到右的时间顺序组织：

```text
参与者
→ 命令
→ 聚合处理
→ 领域事件
→ 策略
→ 后续命令
```

### 3.4 一致性原则

- 同一聚合内部使用本地事务保持强一致；
- 不同微服务之间不使用跨库事务；
- 跨上下文使用同步接口或集成事件协作；
- 所有跨服务写操作必须考虑幂等；
- 核心业务失败后必须有明确补偿路径。

# 5. 身份认证与后台权限事件风暴

## 5.1 管理员登录

### 参与者

- 后台管理员；
- 超级管理员；
- 商品管理员；
- 订单管理员；
- 运营人员；
- 客服人员。

### 主流程

```text
后台管理员
→ 提交管理员登录
→ AdminUser / Account
→ 管理员身份已验证
→ 生成访问令牌
→ 管理员已登录
→ 查询角色和菜单
→ 权限集合已生成
→ 动态菜单已生成
→ 后台完成动态路由注册
```

### 事件明细

| 参与者 | 命令 | 聚合/处理者 | 领域事件 | 后续策略 |
|---|---|---|---|---|
| 后台管理员 | 提交管理员登录 | `AdminUser` / 认证应用服务 | 管理员身份已验证 | 生成访问令牌 |
| 系统 | 生成访问令牌 | 认证服务 | 访问令牌已生成 | 查询角色和权限 |
| 系统 | 加载管理员角色 | `AdminUser` | 管理员角色已加载 | 查询角色菜单 |
| 系统 | 构建权限集合 | `Role` | 权限集合已生成 | 构建动态菜单 |
| 系统 | 构建动态菜单 | `Menu` 查询模型 | 动态菜单已生成 | 返回后台前端 |
| 后台前端 | 注册动态路由 | 前端路由系统 | 动态路由已注册 | 渲染侧边栏 |

### 业务规则

- 禁用管理员不能登录；
- 密码必须经过安全校验；
- 商城会员令牌不能作为后台令牌使用；
- 管理员只能获得其有效角色对应的权限；
- 禁用角色不参与权限计算；
- 隐藏菜单可以不显示，但接口权限仍然独立校验；
- 前端菜单仅用于体验控制，后端接口必须再次验证权限。

### 查询模型

- 当前管理员信息；
- 管理员角色列表；
- 动态菜单树；
- 权限编码集合；
- 当前会话信息。

### 热点

- 角色权限变更后是否立即使已登录令牌失效；
- 是否将权限版本写入令牌；
- 是否使用 Redis 保存登录状态；
- 超级管理员是否绕过普通权限查询；
- 菜单隐藏与权限禁用的区别。

---

## 5.2 角色创建与授权

### 主流程

```text
超级管理员
→ 创建角色
→ Role
→ 角色已创建
→ 分配菜单
→ 角色菜单已分配
→ 分配按钮权限
→ 角色权限已变更
→ 清理权限缓存
```

### 事件明细

| 参与者 | 命令 | 聚合 | 领域事件 | 后续策略 |
|---|---|---|---|---|
| 超级管理员 | 创建角色 | `Role` | 角色已创建 | 可继续分配权限 |
| 超级管理员 | 修改角色信息 | `Role` | 角色信息已修改 | 清理角色缓存 |
| 超级管理员 | 分配角色菜单 | `Role` | 角色菜单已分配 | 重新计算权限 |
| 超级管理员 | 移除角色菜单 | `Role` | 角色菜单已移除 | 重新计算权限 |
| 超级管理员 | 启用角色 | `Role` | 角色已启用 | 用户重新登录后生效 |
| 超级管理员 | 禁用角色 | `Role` | 角色已禁用 | 使角色权限失效 |

### 业务规则

- 角色编码必须唯一；
- 超级管理员角色不能被普通管理员删除；
- 分配给角色的菜单必须存在且有效；
- 按钮权限依附于页面或业务资源；
- 角色禁用后不再提供有效权限；
- 删除角色前需要确认是否仍有管理员绑定；
- 权限变更必须记录操作日志。

## 5.3 管理员创建和角色分配

```text
超级管理员
→ 创建管理员
→ AdminUser
→ 管理员已创建
→ 分配角色
→ 管理员角色已分配
→ 管理员可登录后台
```

### 业务规则

- 管理员账号必须唯一；
- 新管理员必须设置初始密码；
- 管理员至少拥有一个有效角色才有业务权限；
- 禁用管理员不能登录；
- 重置密码应使原有登录状态失效；
- 普通管理员不能修改超级管理员。

## 5.4 菜单维护

```text
超级管理员
→ 创建菜单
→ Menu
→ 菜单已创建
→ 配置路由与权限编码
→ 菜单配置已完成
→ 分配给角色
→ 角色菜单已分配
```

### 业务规则

- 菜单类型包括目录、页面、按钮；
- 权限编码必须唯一；
- 页面菜单必须配置合法组件路径；
- 删除菜单前需要处理子菜单和角色关系；
- 按钮权限不显示在侧边栏；
- 前端只能加载预定义组件映射范围内的组件。

# 6. 商城会员事件风暴

## 6.1 会员注册

```text
游客
→ 提交注册
→ Member
→ 注册信息已校验
→ 会员已注册
→ 会员账号已启用
```

### 业务规则

- 注册功能必须处于启用状态；
- 用户名、手机号或邮箱必须满足唯一性规则；
- 密码必须加密存储；
- 禁止保存明文密码；
- 注册失败不能产生半成品账号。

### 后续策略

- 可自动登录；
- 可发送欢迎消息；
- 可初始化空购物车；
- 可记录注册日志。

---

## 6.2 会员登录

```text
会员
→ 提交会员登录
→ Member
→ 会员身份已验证
→ 访问令牌已生成
→ 会员已登录
→ 游客购物车合并
```

### 业务规则

- 禁用会员不能登录；
- 登录后只能访问自己的资源；
- 游客购物车合并必须幂等；
- 登录失败不应暴露账号是否存在。

---

## 6.3 收货地址管理

### 新增地址

```text
会员
→ 添加收货地址
→ Member / ShippingAddress
→ 收货地址已添加
→ 如为首个地址则设为默认地址
→ 默认地址已变更
```

### 修改默认地址

```text
会员
→ 设置默认地址
→ Member / ShippingAddress
→ 原默认地址已取消
→ 新默认地址已设定
```

### 业务规则

- 会员只能管理自己的地址；
- 同一会员最多一个默认地址；
- 已创建订单使用地址快照，不读取当前地址；
- 删除地址不影响历史订单。

# 7. 商品管理事件风暴

## 7.1 创建商品

### 参与者

- 商品管理员；
- 超级管理员。

### 主流程

```text
商品管理员
→ 创建商品
→ Product
→ 商品已创建
→ 商品处于草稿状态
```

### 输入信息

- 商品名称；
- 商品副标题；
- 分类；
- 品牌；
- 商品描述；
- 商品图片；
- 商品属性。

### 业务规则

- 商品名称不能为空；
- 分类必须存在且有效；
- 品牌必须存在且有效；
- 新商品默认处于草稿状态；
- 草稿商品不能在商城展示；
- 创建商品不等于创建 SKU；
- 创建商品操作需要 `product:create` 权限。

---

## 7.2 配置 SKU

```text
商品管理员
→ 添加 SKU
→ Product
→ SKU 已添加
→ 配置规格与价格
→ SKU 信息已配置
```

### 业务规则

- 同一 Product 内 SKU 规格组合不能重复；
- SKU 编码必须唯一；
- 销售价格不能为负数；
- SKU 默认不一定可售；
- SKU 是否可售还受商品状态和库存影响；
- SKU 变更不影响历史订单快照。

### 热点

- SKU 是否属于 Product 聚合内部实体；
- SKU 数量较多时聚合是否过大；
- SKU 价格变更是否需要独立事件；
- 商品上架后是否允许新增 SKU。

---

## 7.3 上传商品图片

```text
商品管理员
→ 上传商品图片
→ MinIO
→ 文件已上传
→ Product
→ 商品图片已关联
```

### 外部系统

- MinIO；
- 文件上传服务。

### 业务规则

- 文件类型必须合法；
- 文件大小不能超过系统参数；
- 文件上传成功后才能关联商品；
- 删除商品图片时需要处理对象存储文件生命周期；
- 主图必须唯一。

---

## 7.4 初始化库存

商品上下文不直接管理库存，初始化库存需要调用库存上下文。

```text
商品管理员
→ 初始化 SKU 库存
→ Inventory
→ 库存已初始化
```

### 业务规则

- SKU 必须存在；
- 同一 SKU 只能初始化一次库存；
- 初始库存不能为负数；
- 商品服务不能直接写库存表。

---

## 7.5 商品上架

### 主流程

```text
商品管理员
→ 上架商品
→ Product
→ 校验上架条件
→ 商品已上架
→ 发布商品已上架集成事件
→ Search
→ 商品搜索索引已创建或更新
→ 商城可展示商品
```

### 上架条件

- 商品基本信息完整；
- 分类有效；
- 品牌有效；
- 至少一个启用 SKU；
- 至少一个 SKU 价格合法；
- 至少一个 SKU 已初始化库存；
- 商品主图存在；
- 商品未被禁用。

### 领域事件

```text
商品已上架
```

### 集成事件

```text
ProductPublishedIntegrationEvent
```

### 后续策略

- 更新 Elasticsearch 商品索引；
- 清理商品列表缓存；
- 清理商品详情缓存；
- 记录商品上架操作日志。

### 业务规则

- 未满足条件的商品不能上架；
- 重复上架必须幂等；
- 上架不代表一定有库存；
- 商城购买前仍需实时校验商品和库存。

---

## 7.6 商品下架

```text
商品管理员
→ 下架商品
→ Product
→ 商品已下架
→ 发布商品已下架集成事件
→ 搜索索引已删除或标记不可售
→ 商城不再允许购买
```

### 业务规则

- 已下架商品不能加入购物车；
- 购物车中已有商品标记为失效；
- 已创建订单不受影响；
- 历史订单仍展示商品快照；
- 下架操作需要权限；
- 下架事件需要清理缓存和更新搜索索引。

---

## 7.7 修改商品价格

```text
商品管理员
→ 修改 SKU 价格
→ Product
→ SKU 价格已变更
→ 清理商品缓存
→ 更新搜索文档
```

### 业务规则

- 新价格必须合法；
- 价格变化不影响已创建订单；
- 购物车金额需要在查看和结算时重新计算；
- 订单预览必须读取最新价格；
- 提交订单再次校验价格。

---

## 7.8 禁用 SKU

```text
商品管理员
→ 禁用 SKU
→ Product
→ SKU 已禁用
→ 购物车项可能失效
→ 搜索文档已更新
```

### 业务规则

- 禁用 SKU 不能新加入购物车；
- 已在购物车中的 SKU 标记失效；
- 历史订单不受影响；
- 如果商品无任何有效 SKU，应考虑自动下架或禁止购买。

# 8. 商品搜索事件风暴

## 8.1 商品索引同步

### 商品上架同步

```text
商品已上架
→ 策略：同步商品搜索索引
→ 构建 ProductSearchDocument
→ 商品搜索索引已更新
```

### 商品修改同步

```text
商品信息已修改
→ 策略：更新搜索文档
→ 商品搜索索引已更新
```

### 商品下架同步

```text
商品已下架
→ 策略：移除或禁用搜索文档
→ 商品搜索索引已更新
```

### 业务规则

- 搜索文档不是商品聚合；
- 索引同步失败不能回滚商品本地事务；
- 索引同步失败必须重试或补偿；
- 商城购买前不能只依赖搜索文档状态。

---

## 8.2 搜索商品

```text
游客或会员
→ 搜索商品
→ ProductSearchDocument 查询模型
→ 商品搜索结果已生成
```

### 查询条件

- 关键词；
- 分类；
- 品牌；
- 价格区间；
- 是否有货；
- 排序方式；
- 分页。

### 查询模型

- 商品 ID；
- 商品名称；
- 主图；
- 品牌；
- 分类；
- 最低价格；

# 11. 创建订单与库存锁定事件风暴

这是项目最核心的业务流程。

## 11.1 正常创建订单流程

```text
会员
→ 提交订单
→ 校验幂等令牌
→ 查询商品快照与实时价格
→ 校验收货地址
→ 请求锁定库存
→ Inventory
→ 库存已锁定
→ Order
→ 订单已创建
→ 订单状态记录已生成
→ 发送订单延迟关闭消息
→ 清理已结算购物车项
```

### 参与者

- 会员；
- 订单应用服务；
- 商品上下文；
- 库存上下文；
- RocketMQ；
- 购物车上下文。

### 命令与事件表

| 顺序 | 命令 | 处理者 | 事件 |
|---|---|---|---|
| 1 | 提交订单 | 订单应用服务 | 订单提交已受理 |
| 2 | 校验幂等令牌 | 幂等组件 | 幂等令牌已消费 |
| 3 | 获取商品快照 | 商品上下文 | 商品快照已获取 |
| 4 | 锁定库存 | `Inventory` | 库存已锁定 |
| 5 | 创建订单 | `Order` | 订单已创建 |
| 6 | 记录初始状态 | `Order` | 订单状态记录已生成 |
| 7 | 发送延迟消息 | MQ 发布器 | 订单超时检查已安排 |
| 8 | 清理购物车项 | `ShoppingCart` | 已结算购物车项已清理 |

### 订单创建业务规则

- 会员必须已登录；
- 幂等令牌必须有效；
- 商品必须已上架；
- SKU 必须启用；
- 价格必须由服务端计算；
- 地址必须属于当前会员；
- 所有 SKU 库存锁定成功后才能创建订单；
- 任一 SKU 锁定失败则整个下单失败；
- 订单必须保存商品、SKU、价格、图片和地址快照；
- 订单编号必须唯一；
- 初始状态为待付款；
- 重复提交不得创建重复订单。

---

## 11.2 库存锁定成功但订单创建失败

### 异常流程

```text
库存已锁定
→ 创建订单失败
→ 策略：释放库存
→ 库存锁定已释放
→ 订单创建失败已记录
```

### 业务规则

- 释放库存使用相同业务单号；
- 释放操作必须幂等；
- 如果同步释放失败，需要记录补偿任务；
- 补偿任务可通过定时任务重试；
- 不得长期保留无订单关联的锁定库存。

### 热点

- 使用同步补偿还是 Saga；
- 是否采用 Outbox；
- 订单号在锁定库存前还是后生成；
- 库存锁定记录如何关联未创建成功的订单。

---

## 11.3 部分 SKU 锁定失败

```text
请求锁定多个 SKU
→ 部分 SKU 锁定成功
→ 某个 SKU 库存不足
→ 整体锁定失败
→ 释放已成功锁定的 SKU
→ 下单失败
```

### 业务规则

- 库存服务应尽量在本地事务内一次处理同库库存；
- 若分片或多仓导致跨资源，需要明确补偿；
- 第一版可假设单库存服务和单逻辑仓库；
- 返回明确的不足 SKU 信息。

---

## 11.4 重复提交订单

```text
会员重复点击提交
→ 幂等令牌已消费
→ 重复提交已拒绝
```

或：

```text
相同业务请求已创建订单
→ 返回已创建订单结果
```

### 业务规则

- 前端防重复点击不是最终保证；
- 后端必须以幂等令牌或业务唯一键控制；
- 数据库唯一约束作为最后防线。

# 12. 模拟支付事件风暴

```text
会员
→ 支付订单
→ Order
→ 校验订单为待付款
→ 创建或查询支付记录
→ 模拟支付成功
→ 支付已成功
→ Order
→ 订单已支付
→ 订单状态变为待发货
→ 发布支付成功集成事件
→ Inventory
→ 库存已确认扣减
```

### 领域事件

```text
支付已成功
订单已支付
```

### 集成事件

```text
PaymentSucceededIntegrationEvent
```

### 业务规则

- 只有待付款订单可以支付；
- 会员只能支付自己的订单；
- 支付操作必须幂等；
- 已取消订单不能支付；
- 支付成功不能重复确认库存；
- 支付记录和订单状态应在订单服务本地事务内保持一致；
- 库存确认扣减通过同步调用或异步事件完成。

---

## 12.2 重复支付

```text
支付请求重复到达
→ 查询支付记录
→ 支付已成功
→ 返回原支付结果
→ 不重复扣减库存
```

### 业务规则

- 支付编号唯一；
- 支付成功事件消费幂等；
- 库存确认扣减以订单号或业务号幂等。

---

## 12.3 支付成功但库存确认扣减失败

```text
支付已成功
→ 库存确认扣减失败
→ 记录异常
→ 进入重试或补偿
→ 库存确认扣减已完成
```

### 热点

- 支付成功后库存原则上已经锁定，因此失败应属于技术失败而非业务库存不足；
- 是否使用 MQ 重试；
- 是否使用库存确认任务；
- 超过重试次数后如何告警；
- 是否允许订单进入待发货前暂时等待库存确认。

### 第一版建议

```text
支付成功
→ 订单状态改为待发货
→ 发布支付成功事件
→ 库存服务幂等确认扣减
→ 失败后 MQ 重试
→ 定时任务补偿
```

- 不再次减少可用库存；
- 锁定库存减少；
- 已售数量增加；
- 重复确认不能重复扣减。

# 24. 同步调用与异步事件初步划分

## 24.1 建议同步调用

```text

支付订单
后台发货
查询订单
AI 查询商品
AI 查询订单
```

同步调用特点：

- 用户正在等待结果；
- 需要立即确定业务成功或失败；
- 失败需要直接返回明确原因。

## 24.2 建议异步处理

以下操作适合消息驱动：

```text
商品搜索索引同步
订单超时检查
支付成功后的库存确认重试
订单取消后的库存释放重试
操作日志记录
AI 文档解析
向量索引构建
通知类任务
统计数据更新
```

异步处理特点：

- 不要求与主事务同时完成；
- 可以接受短暂延迟；
- 失败后可以重试；
- 需要幂等消费。

# 28. 关键业务不变量

## 28.1 商品不变量

- 草稿商品不能购买；
- 商品上架前必须满足上架条件；
- 无有效 SKU 的商品不能上架；
- SKU 规格组合不能重复；
- 商品历史订单快照不可被当前商品变更覆盖。

## 28.2 订单不变量

- 待付款订单才能支付；
- 待付款订单才能被普通用户主动取消；
- 待发货订单才能发货；
- 已发货订单才能确认收货；
- 已完成订单不能重复完成；
- 已取消订单不能支付；
- 订单金额必须等于订单明细金额汇总；
- 订单归属用户不能变化；
- 订单快照创建后不可随商品变更而变化。

## 28.3 库存不变量

- 可用库存不能小于零；
- 锁定库存不能小于零；
- 同一业务号不能重复锁定；
- 已释放的库存锁定不能再次释放；
- 已确认扣减的锁定不能再次扣减；
- 支付确认扣减必须基于已有锁定记录；
- 库存调整不能直接破坏锁定库存。

## 28.4 权限不变量

- 权限编码必须唯一；
- 禁用管理员不能登录；
- 禁用角色不能提供有效权限；
- 商城身份不能访问后台接口；
- 后台接口必须由后端最终授权。

## 28.5 配置不变量

- 配置键必须唯一；
- 参数值必须符合类型和范围；
- 功能关闭后后端接口不得继续提供该业务能力；
- 系统内置关键配置不能被非法删除。

## 28.6 AI 不变量

- AI 不能凭空生成平台商品；
- AI 不能查询其他用户订单；
- AI 写操作必须经过二次确认；
- AI 不能绕过 Java 领域规则；
- AI 服务故障不能阻断基础交易链路。

# 29. 设计热点与待确认问题

## 29.1 订单与库存一致性

需要进一步确认：

- 订单服务先生成订单号还是先锁定库存；
- 库存锁定成功后订单创建失败的补偿机制；
- 支付成功后库存确认扣减失败的处理；
- 是否引入 Outbox；
- 是否需要 Saga 编排；
- 补偿任务的状态和重试次数。

## 29.2 商品与 SKU 聚合边界

需要进一步确认：

- SKU 是否作为 Product 聚合内部实体；
- SKU 数量很大时是否拆为独立聚合；
- 商品上架规则是否需要领域服务；
- 库存初始化是否属于上架前强制条件。

## 29.3 退款模型

需要进一步确认：

- 退款是否独立聚合；
- 第一版是否只支持整单退款；
- 退款完成后是否回补库存；
- 发货后退款是否需要退货流程；
- 审核拒绝后订单恢复策略。

## 29.4 购物车模型

需要进一步确认：

- 购物车是否采用完整 DDD 聚合；
- Redis 数据如何持久化；
- 游客购物车合并的幂等策略；
- 是否保存加入时价格。

## 29.5 权限生效策略

需要进一步确认：

- 角色权限修改后立即生效还是重新登录生效；
- Token 是否包含权限；
- 权限是否全部存 Redis；
- 超级管理员是否走普通权限模型。

## 29.6 配置影响范围

需要进一步确认：

- 订单超时时间修改是否影响已创建订单；
- 功能开关是否需要版本；
- 配置缓存一致性；
- 是否使用 Nacos 配置或业务数据库配置。

## 29.7 AI 边界

需要进一步确认：

- AI 服务是否保存完整对话；
- 会话数据保留时间；
- 向量数据库选型；
- 工具调用身份如何安全传递；
- 商品对比使用 SPU 还是 SKU；
- AI 响应格式验证失败后的重试策略。
