## 一、需求目标

建立 AI 智能电商微服务平台统一的前端工程基线，同时完成：

- `mall-web` 商城用户端；
- `mall-admin` 后台管理端；

两个 Vue 应用的基础工程。

完成本需求后，两个前端应用都应具备独立：

- 安装依赖；
- 本地启动；
- TypeScript 编译；
- 路由管理；
- 状态管理；
- HTTP 请求；
- 环境配置；
- Layout 布局；
- 代码规范检查；
- 生产构建；

等基础能力，使 M1 及后续商城、后台业务需求可以直接在该工程基线上开发，而不再重复处理前端基础设施问题。

本需求只建立前端工程能力，不开发正式商城和后台业务功能。

## 基础能力要求

至少完成：

### 1. Vue3 + TypeScript + Vite

建立标准 Vue 3 TypeScript 工程。

要求：

* TypeScript 正常工作；
* Vite 开发服务器能够启动；
* Production Build 能够执行；
* 禁止关闭 TypeScript 类型检查来规避问题。

---

### 2. Vue Router

建立 Router 基础能力。

至少支持：

* 路由配置；
* 页面懒加载；
* 404 页面；
* 基础路由守卫扩展入口。

M0 可以只提供：

```text
/
```

以及基础测试页面。

不需要提前建立：

* 商品详情；
* 购物车；
* 订单；
* 用户中心；

等正式业务路由。

---

### 3. Pinia

建立统一状态管理能力。

要求：

* Pinia 正常初始化；
* 建立 Store 目录；
* 为后续用户状态、购物车状态等提供扩展位置。

M0 不提前实现完整：

* UserStore；
* CartStore；
* OrderStore。

允许建立最小示例验证 Pinia 能正常工作。

---

### 4. HTTP 请求基础

基于 Axios 建立统一 HTTP Client。

至少支持：

* `baseURL`；
* timeout；
* Request Interceptor；
* Response Interceptor；
* Header 扩展；
* 错误统一处理入口。

为后续以下能力预留扩展点：

* Access Token；
* Refresh Token；
* TraceId；
* 401 处理；
* 业务错误码处理。

M0 不要求完整实现登录 Token 刷新逻辑。

---

### 5. 环境变量

至少支持：

```text
.env.development
.env.production
.env.example
```

能够配置：

* API Base URL；
* 应用名称；
* 必要的前端环境参数。

真实 Secret、Token、Password 不得写入 Git。

---

### 6. 基础 Layout

建立商城基础 Layout。

例如：

```text
App
└── MallLayout
    ├── Header
    ├── Main
    └── Footer
```

M0 只要求形成可扩展布局结构。

不要求正式完成商城视觉设计。

# 七、API 层规范

后续所有后端调用统一经过：

```text
src/api/
```

或统一 HTTP 基础设施层。

禁止业务页面大量直接写：

```typescript
axios.get(...)
axios.post(...)
```

正确方向：

```text
View / Store
    ↓
API Module
    ↓
HTTP Client
    ↓
Backend
```

例如未来：

```text
api/
├── auth.ts
├── product.ts
├── cart.ts
└── order.ts
```

但是 M0 不需要提前创建这些业务 API 文件。

---

# 八、TypeScript 规范

前端业务数据必须优先定义明确类型。

应建立：

```text
src/types/
```

用于项目级通用类型。

禁止大量使用：

```typescript
any
```

规避类型设计。

HTTP Response、分页等公共类型可以在后续后端接口稳定后逐步建立。

M0 不提前定义完整：

```text
Product
Order
Member
Inventory
```

等业务模型。
