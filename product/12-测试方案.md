# 3. 测试目标

## 3.1 功能正确性

确保以下核心业务流程正确：

```text
注册与登录
→ 商品创建
→ SKU 配置
→ 库存初始化
→ 商品上架
→ 商城浏览
→ 加入购物车
→ 订单预览
→ 创建订单
→ 锁定库存
→ 模拟支付
→ 确认扣减库存
→ 后台发货
→ 用户确认收货
```

同时覆盖：

- 主动取消；
- 超时取消；
- 退款；
- 动态菜单；
- 权限控制；
- 功能开关；
- AI 导购；
- AI 商品对比；
- RAG 客服；
- AI 订单助手。

## 3.2 数据正确性

确保：

- 订单金额正确；
- 商品和地址快照正确；
- 库存数量关系正确；
- 订单状态转换正确；
- 同一请求不重复执行；
- 消息重复消费不产生副作用；
- 缓存失效后可回源；
- 搜索索引最终与商品数据一致。

## 3.3 安全性

确保：

- 未登录请求被拒绝；
- 商城和后台身份隔离；
- 无权限 API 返回 403；
- 用户不能访问他人订单；
- AI 不能绕过业务权限；
- 内部 API 不能被外部直接访问；
- 密码、Token、密钥不泄露；
- 文件上传经过安全校验。

## 3.4 稳定性

确保：

- 服务超时不会导致数据混乱；
- MQ 重复消息可幂等处理；
- 数据库并发不会超卖；
- Redis 异常时有明确降级；
- Elasticsearch 异常不影响核心交易；
- AI 服务异常不影响商城交易；
- 核心补偿任务可以恢复失败状态。

## 3.5 可维护性

确保：

- 领域规则可通过单元测试直接验证；
- 核心接口有自动化回归；
- 契约变更可被检测；
- 测试数据可重复构造；
- 测试结果可追踪；
- 失败用例可通过 TraceId 定位。

# 5. 测试分层

## 5.1 测试金字塔

```text
少量端到端测试
中量集成与契约测试
大量单元测试
```

推荐比例：

```text
单元测试：60%
集成测试：25%
端到端测试：10%
性能与专项测试：5%
```

比例用于指导，不作为强制统计指标。

## 5.2 测试层级

| 层级 | 目标 | 主要技术 |
|---|---|---|
| 领域单元测试 | 验证聚合和不变量 | JUnit 5、AssertJ |
| 应用服务测试 | 验证用例编排 | Mockito、JUnit 5 |
| Repository 集成测试 | 验证持久化 | Testcontainers、MyBatis |
| API 测试 | 验证 HTTP 契约 | MockMvc、WebTestClient |
| 契约测试 | 验证服务和事件契约 | JSON Schema、Pact 可选 |
| 微服务集成测试 | 验证跨服务协作 | Testcontainers、WireMock |
| 前端组件测试 | 验证组件行为 | Vitest、Vue Test Utils |
| 端到端测试 | 验证用户流程 | Playwright |
| AI 测试 | 验证工作流和输出 | Pytest、FastAPI TestClient |
| 性能测试 | 验证吞吐和耗时 | k6、JMeter |
| 安全测试 | 验证权限和攻击面 | OWASP ZAP、自动化脚本 |
| 故障恢复测试 | 验证降级与补偿 | 故障注入、容器停止 |

# 8. 单元测试规范

## 8.1 原则

单元测试应：

- 快速；
- 独立；
- 可重复；
- 不依赖网络；
- 不依赖真实数据库；
- 一个测试只验证一个核心行为；
- 使用明确的 Given-When-Then 结构。

## 8.2 命名

Java 示例：

```text
should_pay_order_when_order_is_pending_payment
should_reject_payment_when_order_is_cancelled
```

中文注释可说明业务语义，但测试方法名建议使用英文。

## 8.3 测试结构

```java
@Test
void should_cancel_order_when_order_is_pending_payment() {
    // Given
    Order order = OrderFixture.pendingPaymentOrder();

    // When
    order.cancel(CancelReason.USER_CANCELLED, now);

    // Then
    assertThat(order.status()).isEqualTo(OrderStatus.CANCELLED);
}
```

## 8.4 禁止做法

- 多个业务场景塞进一个测试；
- 依赖测试执行顺序；
- 使用随机值导致不可复现；
- 只验证方法没有抛异常；
- 单元测试直接访问真实数据库；
- 为提高覆盖率测试无意义 Getter。

# 9. 领域模型测试

## 9.1 Product 聚合

必须覆盖：

### 创建与编辑

- 合法商品可创建；
- 商品名称为空被拒绝；
- 商品编码为空被拒绝；
- 主图唯一；
- 商品属性可以更新；
- 商品分类和品牌可以变更。

### SKU

- 可添加 SKU；
- SKU 编码重复被拒绝；
- SKU 规格组合重复被拒绝；
- 价格小于零被拒绝；
- SKU 可启用和禁用；
- 价格变化产生领域事件。

### 上架

- 资料完整且库存已初始化可上架；
- 缺少主图不能上架；
- 无有效 SKU 不能上架；
- 分类禁用不能上架；
- 品牌禁用不能上架；
- 库存未初始化不能上架；
- 已禁用商品不能上架；
- 重复上架幂等或按规则返回。

### 下架

- 已上架商品可下架；
- 下架产生领域事件；
- 下架不修改历史订单快照。

## 9.2 Order 聚合

必须覆盖：

### 创建订单

- 至少一个订单项；
- 数量必须大于零；
- 金额等于明细之和；
- 地址快照不可为空；
- 初始状态为待付款；
- 支付截止时间正确；
- 创建产生领域事件。

### 支付

- 待付款订单可支付；
- 已取消订单不能支付；
- 已超时订单不能支付；
- 已支付订单重复支付幂等；
- 支付后状态为待发货；
- 记录支付时间；
- 产生支付成功事件。

### 取消

- 待付款订单可取消；
- 已支付订单不能普通取消；
- 已取消订单重复取消幂等；
- 记录取消原因；
- 产生取消事件。

### 发货

- 待发货订单可发货；
- 待付款订单不能发货；
- 已发货订单重复发货按规则处理；
- 物流信息必填；
- 发货后状态为已发货。

### 确认收货

- 已发货订单可确认；
- 待发货订单不能确认；
- 已完成订单重复确认幂等；
- 产生订单完成事件。

### 退款

- 合法状态可申请退款；
- 已取消订单不能退款；
- 已存在进行中退款不能重复申请；
- 退款完成后状态正确；
- 退款拒绝后恢复原状态。

## 9.3 Inventory 聚合

必须覆盖：

### 初始化

- 初始库存为零；
- 正常正数初始化；
- 负数拒绝；
- 同一 SKU 重复初始化拒绝。

### 锁定

- 库存充足可锁定；
- 库存不足失败；
- 锁定后可用减少；
- 锁定后保留增加；
- 同一业务号重复锁定幂等；
- 数量关系始终成立。

### 释放

- 已锁定库存可释放；
- 释放后可用恢复；
- 重复释放幂等；
- 已扣减锁定不能释放。

### 确认扣减

- 已锁定库存可确认扣减；
- 保留库存减少；
- 已售数量增加；
- 重复确认幂等；
- 已释放锁定不能确认扣减。

### 调整

- 增加库存成功；
- 减少可用库存成功；
- 减少超过可用数量失败；
- 不能直接修改锁定数量；
- 每次变化生成库存流水事件。

## 9.4 Role 和 Menu

覆盖：

- 角色编码唯一；
- 禁用角色不提供权限；
- 角色可分配菜单；
- 内置角色不能删除；
- 超级管理员角色不能清空；
- 按钮必须有权限编码；
- 页面组件路径合法；
- 菜单不能形成循环；
- 按钮不能作为父节点。

## 9.5 FeatureConfig 与 SystemParameter

覆盖：

- 功能可启用和关闭；
- 内置配置不能非法删除；
- 参数类型正确；
- 参数范围校验；
- 配置变更产生事件；
- 乐观锁冲突；
- 安全默认值。

# 10. 应用服务测试

## 10.1 测试目标

应用服务测试验证：

- 调用顺序；
- 身份校验；
- 聚合加载；
- 外部端口调用；
- 本地事务结果；
- 事件发布；
- 异常补偿。

外部依赖使用 Mock。

## 10.2 创建订单应用服务

正常场景：

```text
获取当前会员
→ 校验幂等
→ 获取商品快照
→ 获取地址
→ 计算金额
→ 锁定库存
→ 保存订单
→ 发布事件
→ 清理购物车
```

测试应验证：

- 每个端口调用一次；
- 商品价格不取自前端；
- 订单保存完整；
- 返回订单编号；
- 发布订单创建事件。

## 10.3 创建订单失败补偿

覆盖：

- 商品无效时不调用库存；
- 地址无效时不调用库存；
- 库存不足时不保存订单；
- 库存锁定成功但订单保存失败时调用释放；
- 释放失败时创建补偿任务；
- 购物车清理失败不回滚订单。

## 10.4 支付应用服务

覆盖：

- 正常模拟支付；
- 重复支付返回原结果；
- 支付关闭时拒绝；
- 超时订单拒绝；
- 保存支付记录；
- 发布支付成功事件；
- MQ 发送失败时 Outbox 保留。

## 10.5 商品上架应用服务

覆盖：

- 查询分类和品牌状态；
- 查询库存初始化状态；
- 调用聚合上架；
- 保存商品；
- 发布商品上架事件；
- 搜索服务异常不回滚商品本地事务。

## 10.6 权限应用服务

覆盖：

- 角色授权覆盖旧菜单；
- 非法菜单被拒绝；
- 清理相关管理员缓存；
- 记录操作日志；
- 内置角色保护。

# 11. Repository 集成测试

## 11.1 目标

验证：

- SQL 和 Mapper；
- PO 与领域对象转换；
- 索引和唯一约束；
- 乐观锁；
- 事务；
- JSON 字段；
- 查询结果。

## 11.2 环境

使用：

```text
Testcontainers MySQL 8
Flyway
真实 MyBatis-Plus Mapper
```

不建议使用 H2 替代 MySQL，因为：

- JSON 支持不同；
- SQL 方言不同；
- 索引和锁行为不同；
- 时间函数不同。

## 11.3 ProductRepository

覆盖：


验证：

- 未确认不能执行；
- 取消功能关闭不能执行；
- 非待付款不能取消；
- 他人订单不能取消；
- 重复工具调用幂等；
- Java 返回失败时 AI 如实说明。

## 25.3 隐私

AI 回答不得包含：

- 其他会员订单；
- 完整手机号；
- 完整地址；
- 管理员内部信息。

# 27. 稳定性与故障注入

## 27.1 商品服务故障

验证：

- 商品详情可短期缓存；
- 购物车显示降级；
- 下单失败；
- 不使用过期价格完成交易。

## 27.2 库存服务故障

验证：

- 创建订单失败；
- 不生成无库存锁定的订单；
- 已支付订单库存确认进入重试；
- 告警和补偿任务生成。

## 27.3 Redis 故障

验证：

- 权限回源 MySQL；
- 配置回源；
- 商品缓存回源；
- 购物车返回明确失败；
- 不因缓存故障放开权限。

## 27.4 RocketMQ 故障

验证：

- Outbox 保留；
- 恢复后重新投递；
- 不丢失支付和取消事件；
- 重复投递幂等。

## 27.5 Elasticsearch 故障

验证：

- 商品核心交易不受影响；
- 搜索返回降级提示；
- 索引补偿恢复。

## 27.6 AI 服务故障

验证：

- AI 入口返回友好错误；
- 商品、购物车和订单正常；
- 普通搜索可用；
- 不影响 Java 服务线程池。

## 27.7 MinIO 故障

验证：

- 新上传失败；
- 已保存业务数据不被破坏；
- 上传失败有明确错误；
- 文件补偿任务可处理。

## 27.8 MySQL 故障

验证：

- 接口快速失败；
- 连接池不会无限阻塞；
- 恢复后服务健康；
- 事务不产生部分提交。

# 28. 补偿与最终一致性测试

## 28.1 订单创建失败补偿

```text
库存锁定成功
→ 模拟订单数据库失败
→ 释放库存失败
→ 生成补偿任务
→ 恢复库存服务
→ 补偿成功
```

验收：

- 订单未创建；
- 库存最终恢复；
- 补偿任务状态为成功；
- 全过程可追踪。

## 28.2 支付后扣减失败

```text
订单支付成功
→ 库存消费失败
→ MQ 重试
→ 最终确认扣减
```

验收：

- 订单仍为待发货；
- 库存最终为 DEDUCTED；
- 不重复扣减。

## 28.3 取消后释放失败

```text
订单取消
→ 库存释放失败
→ 重试
→ 最终释放
```

## 28.4 搜索索引失败

```text
商品上架
→ 搜索消费失败
→ 重试或补偿
→ 索引最终建立
```

## 28.5 配置缓存失效失败

```text
配置修改
→ 本地缓存未立即删除
→ TTL 过期或事件重试
→ 最终读取新值
```

# 30. Mock 与 Stub 策略

## 30.1 适合 Mock

- 大模型；
- Java 内部 API；
- 文件存储；
- 时间；
- ID 生成器；

以下应使用真实容器验证：

- Redis 数据结构；

- Elasticsearch Mapping；
- MinIO 上传；
- 乐观锁；
- 唯一索引。

## 30.3 时间控制

使用可注入 `Clock`：

```java
Clock fixedClock
```

避免直接调用系统当前时间导致测试不稳定。

测试中使用固定 ID 生成器，便于断言。

# 34. 缺陷等级

## 34.1 阻断级 P0

示例：

- 无法登录；
- 无法创建订单；
- 库存出现负数；
- 重复扣减库存；
- 用户可访问他人订单；
- 商城用户可访问后台；
- 支付成功但订单状态错误；
- 数据库迁移失败。

必须修复后才能发布。

## 34.2 严重级 P1

示例：

- 商品搜索不可用；
- 权限菜单错误；
- 取消后库存长时间不释放；
- AI 推荐不存在商品；
- 配置开关后端未生效；
- 退款状态错误。

原则上发布前修复。

## 34.3 一般级 P2

示例：

- 页面样式错位；
- 文案错误；
- 非核心日志缺失；
- 次要筛选条件异常。

可评估后延期。

## 34.4 建议级 P3

- 体验优化；
- 提示优化；
- 代码可读性；
- 非核心性能优化。
