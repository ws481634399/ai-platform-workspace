# 本地基础设施运行规范

本规范定义 AI Platform 独立基础设施仓的编排、配置、健康检查、数据保留与操作入口约束。后续增加或升级本地中间件时必须遵循本规范。

## 单一编排入口

- `repo-4` 只维护一份共享基础设施 Compose 权威文件，不在 Workspace 或各应用仓复制同一套编排。
- 基础设施使用明确、可获取的非漂移镜像 tag，禁止 `latest` 或省略 tag。
- 首次采用或升级镜像时必须记录实际 RepoDigest，确保测试证据可以追溯到具体镜像内容。
- Compose 服务、端口、网络、卷和凭据变量必须集中声明；应用仓只消费契约，不反向控制基础设施容器。

## 健康与就绪

- 健康检查必须验证真实服务协议或 readiness endpoint，不得仅以容器进程 running 作为 ready。
- 同一服务存在独立 Server、Console 或其他关键入口时，聚合健康检查必须覆盖所有被交付的关键入口。
- 运维健康动作必须在超时时返回失败，并输出服务状态及相关日志入口。

## 配置与凭据

- 真实本地配置写入被 Git 忽略的 `.env`；仓库只提交变量契约和明确标注的隔离本地开发示例。
- 本地示例凭据不得复用到共享、测试、预发布或生产环境，日志和 Evidence 不得输出密码、Token 或 Access Key 值。
- 宿主机端口冲突通过本地 `.env` 显式覆盖；不得自动选择随机端口或修改权威默认契约。

## 数据保留与清理

- 需要保留开发数据的服务使用稳定命名卷；普通 stop/down 不得携带删除卷参数。
- 数据销毁必须是独立、显式且标注不可恢复的操作，不由默认便捷脚本提供。
- 初始化脚本必须幂等并保持职责最小化；业务数据库结构仍由所属服务的 Migration 管理。

## 运维脚本契约

- 脚本只做底层 Docker Compose 的轻量封装，并展示实际执行的 Docker/Compose 命令。
- 脚本必须验证 Action、Service 及开关参数组合，拒绝静默忽略不适用参数。
- 退出码统一为：`0` 表示成功，`1` 表示 Docker、Compose 或健康检查运行失败，`2` 表示参数或本地配置错误。
- 失败信息写入 stderr；运行失败不得被吞掉或转换为成功。

## 验收基线

- 至少验证 Compose 解析与启动、全部关键服务 readiness、容器网络服务名解析和日志可检索性。
- 对有状态服务写入唯一 fixture，执行普通 down/up 后重新读取，并在验收结束清理测试数据但保留开发卷。
- 应用联调必须使用真实客户端或应用进程；代码没有连接入口时标记 PENDING 并记录代码事实，不得用容器探针替代。
