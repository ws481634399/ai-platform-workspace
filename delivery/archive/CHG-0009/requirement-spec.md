# Change Spec（需求总规格）

> 阶段：sdd-prd 产物（多 Story Change 级）
> 输入：`requirement.md`、`exploration.md`

## 0. 元信息

- Change ID: CHG-0009
- Requirement: REQ-M1-003
- 状态流转: exploring → specified

## 1. 背景

CHG-0007/CHG-0008 提供认证和后端授权后，mall-admin 仍需把后端返回的管理员、菜单和权限投影成一致的导航与交互体验。当前 M0 管理端仅有静态路由和占位菜单，无法表达角色差异，也缺少并发 Refresh、403 页面和统一按钮权限。该 Change 建立后续后台业务页面统一接入的前端权限框架。

## 2. 用户价值

- 目标用户: 后台管理员、前端业务模块开发者、平台安全维护人员
- 痛点摘要: 所有管理员看到相同静态菜单；刷新后权限路由丢失；按钮判断散落；401/403 混淆；并发过期请求重复刷新 Token。
- 预期价值: 管理员只看到可访问功能且获得一致异常体验；业务页面用统一元数据和权限原语接入；后端继续承担真实安全边界。

## 3. 功能范围

### 3.1 包含

- [S1] 登录后通过后端接口加载当前管理员基本信息并维护身份状态。
- [S2] 加载菜单树、Permission Codes 和权限版本，建立统一权限状态。
- [S3] 浏览器刷新时恢复合法会话、重建动态路由，并按版本或显式触发刷新权限。
- [S4] 根据可见菜单树渲染层级侧边栏，隐藏禁用或无权节点。
- [S5] 使用编译期组件注册表把受控 componentKey 映射为已知 Vue 页面并动态注册路由。
- [S6] 通过路由守卫区分未认证、无权限和未知页面，分别执行登录跳转、403 与 404。
- [S7] 提供统一 Permission Composable/Directive 控制按钮与操作入口。
- [S8] 多个并发请求遇到 Access Token 过期时共享一次 Refresh，成功后重放，失败后统一清理。
- [S9] 统一处理 401/403，退出或会话失效时移除动态路由、身份、菜单、权限与 Token。

### 3.2 不包含

- 商品、库存、订单和系统配置的具体业务页面。
- 管理员、角色、菜单的后台维护界面（只提供权限框架和可用于验证的基础页面）。
- 以前端权限状态替代后端 API 授权。
- 服务端任意组件路径执行、运行时下载页面代码或 `eval`。
- 商城会员端页面与 mall-web 权限体系。

## 4. 业务规则总纲

- 后端事实源：管理员、菜单、权限和权限版本均以后端响应为准；前端不得根据角色名推导全部权限。
- 安全映射：后端只返回 `componentKey`；前端只映射注册表中已知组件，未知 key 记录告警并拒绝注册。
- 路由幂等：重复引导和权限刷新不得重复注册同名路由；权限移除后旧动态路由必须注销。
- 页面与按钮：页面路由和按钮权限都使用 Permission Code，但隐藏或禁用仅提供 UX，不能表示后端已授权。
- 状态恢复：只持久化恢复所需的最小 Token 信息；管理员、菜单和权限重新从后端获取，不把旧权限永久当作事实源。
- 刷新单飞：同一时间最多一个 Refresh 请求；等待中的请求复用结果且最多自动重放一次，Refresh 接口本身不得递归刷新。
- 401/403 分离：401 表示认证缺失或失效，可刷新或回登录；403 表示已认证但无权限，不得清空有效登录态。
- 清理完整：退出、Refresh 失败或会话撤销时，Token、用户、权限、菜单、动态路由和等待队列必须一致清理。

## 5. 全局验收标准

- [ ] 登录后正确加载当前管理员、菜单树、Permission Codes 与权限版本。
- [ ] 不同权限集合渲染不同菜单、页面路由和按钮入口。
- [ ] 浏览器刷新后可恢复合法会话并幂等重建动态路由。
- [ ] 未知 componentKey 不会加载任意代码；无权限页面进入 403，未知页面进入 404。
- [ ] 多个并发过期请求只发起一次 Refresh，成功重放、失败统一回登录且不循环。
- [ ] 403 不被错误当作登录过期，仍保留合法登录态。
- [ ] 权限变化后前端在目标时间内同步并移除失效入口和路由。
- [ ] 修改 Pinia 或直接调用 API 不能绕过后端 403。
- [ ] mall-admin 单元测试、lint、type-check 与 build 全部通过。

## 6. 非功能需求

- 安全：不把 Refresh Token 暴露给非必要模块；不执行服务端任意组件路径；日志不得输出 Token。
- 性能：一次权限引导只请求必要接口；菜单与路由转换保持线性复杂度；不因每次导航重复拉取权限。
- 可维护性：路由元数据、组件注册表、权限 store、HTTP 刷新协调器和按钮权限原语职责分离。
- 可访问性：403/404/登录页提供明确标题、说明和可操作返回入口。
- 兼容性：保留静态公共路由；动态业务路由可由后续模块按注册表扩展。

## 7. 成功指标

- mall-admin 权限框架单元测试、lint、type-check 和 build 通过率 100%。
- 并发 Access Token 过期场景中每批请求只产生 1 次 Refresh 调用，自动重放不超过 1 次。
- 未知组件 key 加载成功数为 0；权限移除后旧菜单、路由和按钮残留数为 0。
