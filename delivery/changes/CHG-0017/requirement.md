# Requirement

> 原始需求全文归档于 `references/M3.md`（REQ-M3-002 第一至十二章 + 文末注意点 4、5），本文件记录本 Change 的输入边界。

## 需求描述

按 `docs/需求/M3/M3.md` 中 `REQ-M3-002 商城商品浏览体验` 执行完整 SDD。基于 M2 已交付的 Product/SKU 与 Inventory 权威数据，实现消费者侧浏览链路：商城首页 → 分类浏览 → 商品列表 → 商品详情 → 选择 SKU → 查看价格与可售状态。**必须使用真实后端数据，禁止静态 Mock 商品作为最终实现。**

**新增商城公开 API（M3.md 文末注意点 4 明确要求）：**

- `GET /api/mall/categories/tree`：仅返回有效（启用）分类树；
- `GET /api/mall/brands`：仅返回有效品牌，支持基础分页/筛选；
- 商品列表补齐排序参数；
- 批量 SKU 可售状态查询（供详情/购物车聚合）；
- 商品详情所需库存的聚合方式（服务端聚合，浏览器不访问 `/api/internal/**`，列表不得逐个查库存造成 N+1）。

**首页：** 分类入口与商品展示位（新品/推荐/热门基础结构、Banner 位可占位），运营策略不复杂化，目标是“真正能够进入商品浏览路径”；展示数据全部真实。

**分类浏览：** 只展示有效分类与其下有效商品；后台禁用分类后商城不可见，符合 M2 规则。

**商品列表：** 分页、分类筛选、品牌筛选、基础排序、商品图片/名称/价格；直接查 Product 服务数据库即可，不引入 Elasticsearch/全文搜索/复杂聚合（M5）。

**商品列表价格规则（M3.md 文末注意点 5）：**

- 返回每个商品启用 SKU 的最低价/最高价（minPrice/maxPrice）；
- 无有效（启用）SKU 的商品不得出现在商城；
- 金额统一整数分，禁止浮点数。

**商品详情与 SKU：** 展示名称、图片、品牌、分类、介绍、SKU 及规格属性、SKU 价格、必要可售状态；严格区分 Product 与 SKU，加入购物车的目标是 skuId 而非 productId；规格组合（如颜色+容量）解析到唯一 SKU，切换 SKU 时价格/图片/可售状态随真实 SKU 联动。

**库存展示（展示信息，非交易保证）：**

- Product 不拥有库存，库存状态经服务间 Java API 从 mall-inventory 获取并聚合；
- 用户可见状态：有货 / 库存不足 / 缺货（阈值由 Design 定），不要求展示精确数字；
- 商品页“有库存”不代表稍后下单成功；真正校验在 M4 锁库存。商品页库存 = 展示信息，订单锁库存 = 交易约束。

**游客访问：** 首页、分类、商品列表、商品详情原则上无需登录；需会员身份的动作再引导登录。

**错误与空状态：** 商品不存在、已下架、SKU 失效、暂无库存、网络错误、空分类、空列表均需有 Loading/Empty/Error 处理，不得白屏或仅抛 JS 异常。

## 补充信息

- 优先级：P0
- 前置依赖：REQ-M2-003、REQ-M2-004；CHG-0015（网关公开路由、字符串 ID、价格区间修复）
- 主要服务：mall-product、mall-inventory（服务端聚合）、mall-gateway（公开路由）
- 主要前端：mall-web
- 主要仓库：repo-1、repo-2
- 非本需求范围：Elasticsearch/全文搜索（M5）、AI 推荐、收藏、评论、营销、优惠券、加购物车（CHG-0018）、下单、支付。
- 验收补充：mall-web build / lint / type-check 必须通过。
