# Change Spec（需求总规格）

> 阶段：sdd-prd 产物（多 Story Change 级）
> 输入：`requirement.md`、`exploration.md`

## 0. 元信息

- Change ID: CHG-0007
- Requirement: REQ-M1-001
- 状态流转: exploring → specified

## 1. 背景

M0 已交付 Java 微服务、Gateway、公共模块、mall-admin 与本地 MySQL/Redis 基线，但系统尚无可复用的统一认证闭环。M1 必须先建立后台管理员认证和跨服务身份基础，后续 RBAC 与会员认证才能在同一主体模型、Token 语义和 SecurityContext 上演进。本 Change 是新增安全基础，不替代既有业务能力，与已批准知识无冲突。

## 2. 用户价值

- 目标用户: 后台管理员、受保护业务服务、平台运维与安全审计人员
- 痛点摘要: 管理员无法安全登录；服务无法区分调用主体；Token 缺少可刷新和可撤销生命周期；下游没有可信身份上下文。
- 预期价值: 管理员可安全建立和终止登录态，Gateway 与业务服务共享一致身份语义，RBAC 与 M3 会员认证可复用同一认证基础。

## 3. 功能范围

### 3.1 包含

- [S1] 安全存储管理员密码并在认证前校验账号启用状态。
- [S2] 校验管理员用户名与密码，返回稳定且不泄密的认证结果。
- [S3] 签发带类型、受众、签发时间和过期时间的 Access Token 与 Refresh Token。
- [S4] 仅接受有效、未撤销且匹配 ADMIN 主体的 Refresh Token，并执行轮换。
- [S5] 主动退出或管理员禁用后撤销会话，使旧 Refresh Token 不能再换取新凭证。
- [S6] 定义 GUEST、MEMBER、ADMIN、SERVICE 主体并拒绝主体、issuer 或 audience 混用。
- [S7] 在 Java 服务建立统一 SecurityContext，提供 subjectId、subjectType、username、traceId。
- [S8] Gateway 初验 Token、清除客户端伪造身份头并向下游传播可信身份。
- [S9] mall-admin 提供登录表单、认证调用、基础 Token 状态和退出入口。

### 3.2 不包含

- 完整管理员、角色、菜单与权限管理（CHG-0008）。
- 动态菜单、动态路由与按钮级权限框架（CHG-0009）。
- 商城会员注册、资料、地址与完整会员认证流程（M3）。
- 商品、库存、订单的资源归属授权规则。
- 第三方登录、MFA、短信验证码和找回密码。

## 4. 业务规则总纲

- 凭证保密：密码只保存自适应哈希；任何响应、异常和普通日志均不得包含密码、摘要、完整 Token 或签名密钥。
- 登录资格：账号不存在、密码错误、账号禁用均不得建立登录态；对外失败信息避免账号枚举，对内保留可审计原因。
- 双 Token：Access Token 短时有效；Refresh Token 生命周期更长但必须可撤销、可轮换，轮换后的旧 Token 不可重放。
- 主体隔离：所有已认证 Token 必须包含受控 subjectType；管理端接口只接受 ADMIN，服务身份只用于明确的服务间场景。
- 边界分离：Gateway 判断凭证有效性并传播身份；业务服务不得把 Gateway 通过等同于业务授权通过。
- 身份头防伪：Gateway 必须先删除外部请求携带的内部身份头，再写入校验后的规范身份信息。
- 状态失效：管理员禁用至少阻止新登录与 Refresh；受保护请求按设计检查会话/主体版本，不能无限期依赖旧状态。

## 5. 全局验收标准

- [ ] 正确凭证可获得 Access Token 与 Refresh Token，错误凭证和禁用账号被拒绝。
- [ ] Access Token 可被 Gateway 与下游服务识别，过期或主体不匹配的 Token 被拒绝。
- [ ] Refresh Token 可轮换，过期、撤销或已轮换 Token 不能再次使用。
- [ ] 主动退出与管理员禁用按设计使会话失效。
- [ ] ADMIN、MEMBER、SERVICE Token 不能跨受众或主体边界混用。
- [ ] SecurityContext 可稳定读取 subjectId、subjectType、username、traceId。
- [ ] 外部伪造身份头不会进入下游可信上下文。
- [ ] mall-admin 可登录、刷新和退出，退出后不保留有效认证状态。
- [ ] 自动化测试覆盖正常、错误、过期、撤销、重放、主体混用和敏感信息保护场景。

## 6. 非功能需求

- 安全：采用业界标准密码哈希和签名算法；密钥仅从受控配置加载；认证端点具备基础防暴力破解能力。
- 性能：不访问外部依赖时，Token 本地验证 P95 目标低于 20ms；登录与刷新 P95 目标低于 300ms（不含网络）。
- 可用性：Refresh 并发与轮换应产生确定性结果，不得生成无法追踪的多条并行会话链。
- 可观测性：认证失败按受控原因分类并关联 traceId，日志脱敏。
- 兼容性：为 M3 的 MEMBER 和服务间 SERVICE 预留统一主体结构，不在本期开放会员功能。

## 7. 成功指标

- 认证核心自动化用例通过率 100%，无未关闭高危安全发现。
- 合法 Token 本地验证 P95 低于 20ms，登录与刷新 P95 低于 300ms（测试环境、不含网络）。
- 日志与 API 响应敏感信息扫描中密码、摘要、完整 Token 和密钥泄露项为 0。
