## 1. 背景

M1 已交付统一身份认证（CHG-0007）、后台 RBAC（CHG-0008）与动态菜单权限前端（CHG-0009），平台具备了"谁能操作"的安全底座，但 mall-product 中还没有任何可供组织商品的业务主数据。进入 M2 后，商品 SPU/SKU（REQ-M2-002）、发布与商城查询（REQ-M2-003）都要求商品能够绑定一个合法、稳定、可启停的分类与品牌；若分类可成环、父节点可悬空、品牌可重名或已停用数据仍可被新商品引用，后续商品建模与上架校验将失去可信前提。

本需求在 Product Context（mall-product）建立 Category 树形聚合与 Brand 聚合两类基础主数据，并在 mall-admin 提供后台维护页面，操作全部接入 M1 的 RBAC 与动态菜单体系。exploration §4 冲突检测结论：与 product/specs/ 无冲突、与已归档 Change 无范围重叠，仅沿用 CHG-0008/0009 的权限注解与前端权限机制，不回改归档 Change。

## 2. 用户价值

- 目标用户: 超级管理员、商品管理员（后台）；间接受益方为后续商品维护流程与商城购物用户；系统侧消费方为 Product/SKU 建模与商品上架校验。
- 痛点摘要: 平台没有统一的商品分类骨架与品牌库；无法以层级方式组织商品；缺少分类循环/悬空父级等脏数据防护；主数据启停无管控会导致无效分类/品牌被商品引用。
- 预期价值: 商品管理员可可视化维护多级分类树与品牌库，排序稳定、启停可控；系统保证只有合法且启用的分类/品牌能被商品引用，为 REQ-M2-002/003/004 提供可信主数据基础。

## 3. 功能范围

### 3.1 包含

- [S1] 创建分类：指定名称、父分类（可为空表示一级）、排序值，建立父子层级关系。
- [S2] 修改分类：修改名称、调整父分类（移动层级）、调整排序，保存时执行层级与循环校验。
- [S3] 查询分类：分类详情查询与一次性返回全量分类树（含层级、启停、排序），供后台与下拉选择使用。
- [S4] 启用/禁用分类：切换分类可用状态；禁用分类不可被新商品绑定、不可在其下新建子分类。
- [S5] 创建/修改品牌：维护品牌名称（全局唯一）、Logo 地址、描述、排序。
- [S6] 查询品牌：品牌分页列表，支持名称关键字筛选与排序，供后台列表与商品表单选择。
- [S7] 启用/禁用品牌：切换品牌可用状态；禁用品牌不可被新商品绑定。
- [S8] 分类后台维护页面与权限：mall-admin 分类树/列表、新增、编辑、启停界面，操作受 product:category:* 权限码控制。
- [S9] 品牌后台维护页面与权限：mall-admin 品牌列表、新增、编辑、启停界面，操作受 product:brand:* 权限码控制。

### 3.2 不包含

- Product/SPU、SKU 及其属性、价格、图片维护（REQ-M2-002）。
- 商品上下架、商城列表/详情、商品快照与内部查询契约（REQ-M2-003）。
- 库存数量、锁定与扣减（REQ-M2-004，mall-inventory）。
- 文件存储/上传系统：品牌 Logo 与分类图片仅保存外部 URL/Object Key，MinIO 上传能力不在本需求实现。
- Elasticsearch 检索与 AI 推荐（M5/M6）。
- 主数据的物理删除能力：本需求不提供物理删除 API（含被引用与未被引用数据），数据退出统一通过"禁用"表达。
- 分类/品牌的批量导入导出、多语言、多店铺/多租户隔离。

## 4. 业务规则总纲

- 层级上限（解决 exploration §5 待澄清 1）：分类树最多 **3 级**；创建/移动后层级超过 3 级 → 拒绝并提示"分类最多支持 3 级"。
- 层级合法性：分类不能以自身为父（自引用）→ 拒绝；不能形成循环（新父节点是自己的后代）→ 拒绝；父分类必须存在 → 不存在则拒绝；禁用分类不能作为新建子分类的父级 → 拒绝。
- 排序稳定：同级分类按 sort 升序、再按创建时间/ID 稳定次序返回；sort 为整数，默认值由设计确定；调整排序不改变其他业务数据。
- 禁用影响面（解决 exploration §5 待澄清 2）：禁用分类/品牌是"准入开关"——新商品创建与上架校验不得引用已禁用对象；**不级联处置存量商品、不强制下架**（存量商品是否可售由 REQ-M2-003 上架校验独立判定）。禁用父分类不自动禁用子分类，但子分类在选择器中以父级禁用态置灰提示。
- 删除策略（解决 exploration §5 待澄清 3）：不提供物理删除；数据生命周期仅"启用/禁用"。需求文档中"删除受限制"以禁用兜底实现，避免任何引用悬空。
- 品牌唯一性（解决 exploration §5 待澄清 6）：品牌名称全局唯一（忽略首尾空格），重复创建/改名 → 拒绝并提示"品牌名称已存在"。
- 权限编码（解决 exploration §5 待澄清 4）：分类 `product:category:list`、`product:category:create`、`product:category:update`、`product:category:disable`；品牌 `product:brand:list`、`product:brand:create`、`product:brand:update`、`product:brand:disable`。菜单挂到后台"商品管理"一级菜单下的"分类管理""品牌管理"项。
- 查询形态（解决 exploration §5 待澄清 5）：分类树一次性返回全量（不分页，数据量可控）；品牌列表分页并支持名称关键字模糊筛选。
- 图片地址：Logo 仅保存字符串地址（URL 或 Object Key），本服务不存储二进制文件。
- 授权边界：后端在每个写 API 上真实校验权限码并返回 403；前端隐藏入口不构成安全边界（沿用 M1 原则）。

| AC-001 | 给定有 product:category:create 权限的管理员，当提交合法一级分类（名称+sort）时，则创建成功并可在分类树根节点查到。 | S1 |
| AC-002 | 给定一个已存在一级分类，当以其为父创建子分类且层级不超过 3 级时，则创建成功，分类树中出现在正确父节点下。 | S1 |

| AC-004 | 给定分类 A 及其后代 B，当把 A 的父分类修改为 B（或 B 的后代）时，则被识别为循环并拒绝，层级数据不变。 | S2 防循环 |
| AC-005 | 当创建/移动分类指定的 parentId 不存在时，则请求被拒绝并提示父分类不存在。 | S2 |
| AC-006 | 给定一个含子类的三级分类树，当尝试在三级分类下再建子分类时，则被拒绝并提示最多 3 级。 | S1/S2 层级上限 |
| AC-007 | 当调用分类树查询接口时，则一次性返回全部分类，按层级嵌套、同级按 sort 与稳定次序排列，包含启用状态字段。 | S3 |
| AC-008 | 给定启用分类，当执行禁用后，则该分类不出现在商品表单可选父级/分类中，且不可在其下新建子分类；重新启用后恢复可选。 | S4 |
| AC-009 | 给定品牌创建接口，当两次提交相同名称（含仅首尾空格差异）时，则第二次被拒绝并提示名称已存在。 | S5 唯一约束 |
| AC-010 | 给定合法品牌信息（名称/Logo URL/描述/sort），当创建并随后修改描述与排序时，则查询返回最新值。 | S5 |
| AC-011 | 当以名称关键字分页查询品牌时，则只返回名称匹配的品牌且分页参数正确生效，结果按排序规则返回。 | S6 |
| AC-012 | 给定启用品牌，当执行禁用后，则该品牌不可被新商品引用；重新启用后恢复可引用。 | S7 |

| AC-014 | 给定具备菜单权限的管理员登录 mall-admin，当进入分类管理/品牌管理页时，则可完成树展示、新增、编辑、启停全流程操作并看到成功/失败反馈。 | S8/S9 端到端 |
| AC-015 | 系统不存在任何分类/品牌物理删除入口；对已产生或未产生引用的数据，退出均通过禁用完成，不产生引用悬空。 | 删除策略 |
| AC-016 | 分类防自引用、防循环、防悬空父级、层级上限、品牌名称唯一等核心领域规则具备自动化测试且全部通过。 | 领域规则 |

## 6. 非功能需求

- 安全：全部接口经网关认证与服务端权限码校验，默认拒绝；写操作记录操作者（沿用 M1 审计能力，不在本需求重建审计系统）。
- 性能：分类树全量查询 P95 低于 200ms（M2 数据规模下）；品牌分页列表 P95 低于 300ms。
- 一致性：名称唯一、层级不变量由数据库约束与服务端事务双重保证；并发改名不产生重复品牌。
- 兼容性：接口遵循 M1 统一返回结构 UnifyResult 与既有异常码规范；前端复用 mall-admin 既有布局、HTTP 客户端与权限指令。
- 可扩展性：分类/品牌模型为后续 Product 绑定、商城筛选预留稳定 ID 与状态字段。

## 7. 成功指标

- 核心领域规则（防循环/悬空/层级/唯一）自动化测试通过率 100%，上线后零循环、零悬空父级、零重名品牌数据事故。
- 商品管理员可在 mall-admin 无协助完成分类树与品牌日常维护，单次维护操作平均 ≤ 1 分钟。
- 本期为基础主数据，不设业务转化类指标；以上为可观测的质量与效率指标。
