## 1. 需求要点

- 做什么：为 mall-product 建立分类树与品牌两类基础主数据，提供列表/树、新增、编辑、启用/禁用与正则排序的后台维护能力，商品侧可引用合法分类与品牌。
- 给谁：后台管理员（含商品管理员角色）；下游消费方为 Product/SKU 建模与商品上架校验。
- 解决什么问题：为 M4 订单、M6 AI 导购提供稳定商品组织基础；M2 之前平台无以统一分类/品牌组织商品的骨架。
- 隐含需求：
  - 分类防循环（ParentId 校验 + 层级路径约束）、防自引用、父分类必须存在；
  - 分类/品牌删除策略：已产生业务引用（被商品使用）的分类与品牌不能物理删除，禁用兜底；
  - 分类层级上限需 Design 确定，删除父分类前需处理子分类；
  - 品牌 Logo 走 MinIO 文件地址（M2 不实现文件存储系统）；
  - 后台操作受 RBAC 保护（Permission Code 形如 product:category:*、product:brand:*，Design 确定）；
  - 排序稳定、结构化查询（分类树一次性返回）。

知识检索结果（引用来源）：

- `product/06-聚合与领域模型设计.md` §7.2 Category 聚合 / §7.3 Brand 聚合：聚合结构、领域行为与不变量与本文档一致（防循环、被引用不物理删除、品牌名称唯一、禁用品牌不用于新商品）。
- `product/04-子域与限界上下文.md` BC-03 Product Context（mall-product）：Category/Brand 归属商品上下文。
- `product/11-权限与功能配置.md` §11.5/§11.6/§11.7 与权限矩阵：商品管理员可维护分类品牌，库存只读等角色边界已规划。
- `product/05-上下文映射图.md`：商品上下文为后续 Cart/Order/Search/AI 的上游 Supplier。

## 5. 待澄清问题

- 分类允许的最大层级数 → 需在 prd/design 阶段确定（需求标注"由 Design 阶段确定"）。
- 禁用分类后存量商品的处理规则（上架校验拦截 / 商品下架 / 仅新建拦截）需 prd 明确。
- 删除策略落点：需求明确"不物理删除已产生业务引用的分类"，但"软删除还是仅禁用"需 design 统一（倾向禁用兜底 + 引用计数）。
- Category/Brand 的 Permission Code 精确编码与菜单项归属需 design 阶段确认。
- 品牌/分类列表查询的分页与筛选维度（仅排序 or 含关键字）由 design 细化。
- Brand 名称唯一性规则（全局唯一）需在规格中确认并落地唯一约束。
